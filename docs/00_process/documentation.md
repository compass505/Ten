# ドキュメント規約

種別: リファレンス（規約）
根拠: [調査](../10_requirements/research/documentation.md) / [ADR-0004](../10_requirements/decisions/ADR-0004-documentation-policy.md)
状態: 確定
更新トリガー: ドキュメントが増えて置き場に迷ったとき / 読み手が増えたとき

---

## 1. 読み手

| 読み手 | 前提 | 効くもの |
| --- | --- | --- |
| 未来の自分 | 3 週間後には理由を忘れている | **なぜそう決めたか** |
| AI エージェント | 会話履歴を持たない。文脈は毎回ゼロから | **自己完結した規約と手順** |
| （将来）利用者 | まだ存在しない | チュートリアル・ハウツー |

**当面の読み手は上 2 つだけ。** 利用者向けドキュメントはアプリが動いてから書く。
今それを書くと、実体のないテンプレートが増えるだけになる。

## 2. 4 分類のうち 2 つだけ使う

Diátaxis の分類を借りるが、当面使うのは 2 種。

| 種別 | 使う | 置き場 | 書き方 |
| --- | --- | --- | --- |
| リファレンス（規約・事実） | ○ | `docs/00_process/` `docs/20〜30_*` `docs/40_test/` | 表と箇条書き。理由を書かない |
| 説明（なぜ） | ○ | `docs/00_process/rationale.md` `decisions/` | 散文。トレードオフを書く |
| ハウツー（手順） | △ | `.claude/skills/` | 繰り返す手順のみ。2 回目に切り出す |
| チュートリアル | ✕ | — | 利用者ができてから |

**1 ファイル 1 役割。規約と理由を同じファイルに混ぜない。**
規約は頻繁に参照され、理由は一度読めばよい。混ぜると規約が読みにくくなる。

## 3. 置き場の判断

```
その情報は…
├ 決定であり、覆すのに理由が要る          → decisions/ADR-xxxx（不変）
├ 決定の材料であり、出典がある            → 10_requirements/research/
├ 常に守るべきルール                      → 00_process/ の規約ファイル
│   └ そのうち「エージェントが毎回守る」もの → CLAUDE.md（短く）
├ 繰り返す手順                            → .claude/skills/
├ フェーズの成果物                        → 該当フェーズの docs/
└ まだ決まっていない論点                  → 10_requirements/open_issues.md
```

## 4. ADR の運用

- 1 件 1 決定。連番 `ADR-xxxx-英語スラッグ.md`
- 構成: 背景 / 選択肢 / 決定 / 結果（トレードオフ）
- ステータス: `Proposed` → `Accepted`（人間が承認した時点） → `Superseded by ADR-xxxx`
- **確定した ADR は書き換えない。** 覆すときは新しい ADR を切り、旧を Superseded にする
- 書くのは「**後から理由を思い出せないと困る決定**」だけ。
  可逆で安い決定を ADR にすると、決定ログがノイズで埋まる

判断基準: **後戻りコストが 1 日を超えるか？** 超えないなら ADR にしない。

## 5. CLAUDE.md の運用

`CLAUDE.md` は毎回読み込まれる。**常に効くものだけを書く。**

- 各行について「これを消したら間違いが起きるか？」を問う。起きないなら消す
- 長い `CLAUDE.md` は無視される。重要な指示がノイズに埋もれる
- たまにしか要らない知識・手順は**スキルに出す**（必要なときだけ読み込まれる）
- 目安として 200 行を超えたら削る対象を探す

## 6. テンプレートと実体を分ける

テンプレートは `_templates/` に置く。実体と同じディレクトリに置かない。
（`ADR-0000-template.md` が ADR 一覧に混ざるのを防ぐ）

## 7. 更新トリガーを書く

**各規約ファイルの冒頭に「何が起きたらこれを直すか」を書く。**
更新の条件が書かれていないドキュメントは、必ず腐って嘘になる。

## 8. 書かないもの

| 書かない | 理由 |
| --- | --- |
| コードを読めば分かること | 二重管理になり、必ず片方が嘘になる |
| ファイルごとの説明一覧 | 更新されない筆頭 |
| 「きれいに書く」等の一般論 | 判断に使えない |
| 頻繁に変わる数値をハードコードした説明 | 実体（設定ファイル）を参照させる |
