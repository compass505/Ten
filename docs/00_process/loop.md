# ループ規約

種別: リファレンス（規約） — 理由は [rationale.md](rationale.md) に分離
根拠: [調査](../10_requirements/research/dev_loop.md) / [ADR-0003](../10_requirements/decisions/ADR-0003-improvement-loop.md)
状態: **確定（自動化の段階だけ、必要になった時点で上げる）**
更新トリガー: 自動化の段階を上げたとき / 3 周連続で成果が出なかったとき

---

## 0. ループは 2 種類ある。混ぜない

| | 実行ループ | 改善ループ |
| --- | --- | --- |
| 目的 | 決まった仕様を満たす | 仕組みを良くする |
| 判定 | チェックが green | 目標条件を満たしたか |
| 頻度 | 分〜時間 | 日〜フェーズ単位 |
| 主体 | エージェントが自走してよい | 人間が判断を持つ |
| 記録 | 不要（テスト結果が残る） | **必須**（`loop_log.md`） |

---

## A. 実行ループ

**「自分で走らせられるチェック」があるときだけ自走させる。** ないなら作るのが先。

```
実装 → チェック実行 → 結果を読む → 直す → …（green まで）
```

### チェックとして認めるもの

合否が機械的に返るもの。テスト / ビルドの終了コード / 型チェック / リンタ /
出力とフィクスチャの差分。**「動いているように見える」は認めない。**

### 停止条件を強める段階

必要になるまで上げない。上から順に、準備コストと引き換えに拘束力が上がる。

| 段階 | 手段 | 使いどころ |
| --- | --- | --- |
| 1 | 同じ指示の中に「チェックを走らせて直せ」と書く | 常時。これが基本 |
| 2 | セッションの達成条件として設定する | 長い作業を任せるとき |
| 3 | フックでチェックが通るまでターンを終わらせない | 何度も同じ抜けが起きたとき |
| 4 | 別文脈のレビューを挟む | 自己採点を避けたいとき |

### やらないこと

- チェックを通すためにチェック自体を緩める（テストの書き換え、閾値の引き下げ）
- 「成功しました」で終わらせる。**証拠（実行したコマンドと出力）を残す**
- 同じ指摘を 2 回して直らないのに、同じ文脈で 3 回目を試す
  → 文脈を切って、学んだことを織り込んだ指示を書き直す

## B. 改善ループ

対象は**仕組みの側**: ハーネスの書き味・ワークフロー定義・スキル・検証スクリプト、
および「テストが green のまま直せる範囲」の実装品質。

**要件を改善ループで動かさない。** 要件を変えるときは
[workflow.md](workflow.md) の「フェーズを戻るときのルール」に従う。

### 1 周の形

```
現状把握 → 目標条件 → 障害 → 変更（小さく） → 検証 → 記録
```

| 段階 | やること | 回さない条件 |
| --- | --- | --- |
| 現状把握 | 事実を集める。落ちたテスト・かかった時間・詰まった箇所 | **事実がなく印象しかない → 回さない** |
| 目標条件 | 「何がどうなれば成功か」を**測定可能な形で先に書く** | **書けない → 回さない** |
| 障害 | 目標条件との差を埋めるのに邪魔なものを列挙 | 障害が 2 つ以上 → 周を分ける |
| 変更 | 最小の変更を入れる | 影響が広範囲 → 先に ADR を書く |
| 検証 | チェックを通す。**予測が当たったかを明示する** | red のまま次の周に進まない |
| 記録 | `loop_log.md` に 1 ブロック残す | **記録しない周は「やっていない」と同じ** |

### 守ること

- **同時に追う改善パスは 1 本。** 2 つ気になったら周を分ける
- 目標条件は「良くする」ではなく測れる形で書く
  （✕「ハーネスを書きやすくする」 ○「TC 1 件を書くのに触るファイルを 3 → 1 にする」）
- 検証で「予測は外れた」と書ける周は成功。学びが残る。
  外れたことを書かずに目標条件を後から書き換えるのが一番まずい

### 止めどき

- 目標条件を満たした → その周は終わり
- **3 周連続で同じ場所を触っている** → ループの問題ではなく設計の問題。
  設計フェーズに戻る
- 事実が集まっていない → 回さずに、まず観測する手段を作る（`tools/`）

## C. トリガー

| きっかけ | 回すループ |
| --- | --- |
| 実装中、テストが red | A |
| フェーズ完了時 | B（そのフェーズで何が重かったかを振り返る） |
| 同じ作業を 2 回繰り返した | B（スキル化を検討する） |
| 詰まって 2 回直しても直らない | B（仕組み側に原因がある疑い） |
