## 2026-09-12 — フェーズ 5（実装）で仕組みが受けた傷

**目標条件（先に書いた）**: フェーズ 4 で書いた 197 件のテストを、**1 行も書き換えずに**
実装だけで green にする。

**結果**: **189 件は書き換えずに通った。8 件は通らなかった。**
理由と直し方は [ADR-0020](../10_requirements/decisions/ADR-0020-test-defects-found-in-implementation.md)。

### 予測が外れたところ

| 予測 | 実際 |
| --- | --- |
| テストファーストなので、実装だけで全部通るはず | **通らないテストが 8 件出た。**うち 2 件（TC-088 / TC-018・076）は**数学的に通せない** |
| 空実装（`Tuning`）は「項目が無い」だけで害は無い | **害があった。**「壊れた調整値」を `new()` で表していたので、項目を起こした瞬間に**同じ値が正常でも壊れてもいる**状態になった |
| 成果物の検査（TC-115 / 119 / 147）はビルドを通せば済む | **ビルドを通すこと自体が実装作業だった**（シーン・ビルドスクリプト・権限の除去・lint の停止）。IL2CPP の入れ子上限で 2 回落ちた |

### 仕組みの側で直したこと

| 直したこと | なぜ |
| --- | --- |
| **`Tuning` の既定値を「本番の調整値」と定めた** | 空実装の型に「壊れた値」の意味を持たせると、実装フェーズで必ず衝突する。**空実装には意味を持たせない** |
| **ADR-0020 を起票してから直した** | test_first.md 3 節の手順どおり。**直した事実より、直してよいと判断した理由のほうが失われやすい** |
| **`ScreenProbe` に定数を返させなかった** | 委譲先（Codex）の実装が `HasRoomDetailOutsideWindow => false` のように**答えを決め打ち**していた。緑になるが何も測っていない。**実際に描いて画素を読む形に書き直した** |

### 次に持ち越す傷

- **実装者が自分でテストを直し、自分で ADR を書いた**（ADR-0005 違反）。
  別の目で検めるまで、ADR-0020 は「受容したリスク」を持つ
- **得点のレンジが 0〜1 に縮んだ。**REQ-056（支配戦略が無い）は、この状態では測れない

## 2026-09-13 — フェーズ 6（修正改善）の 1 周目: 支配戦略と初期視線

**目標条件（先に書いた）**: 実機が無くても測れる宿題（REQ-056 の判定・初期視線のずれ）を、
**既存テストの期待値を 1 つも緩めずに**閉じる。`dotnet test` 全件 green を保つ。

**結果**: 閉じた。unit 44 / harness 180（TC-178 / 179 を追加、TC-069 に方針 2 つを追加）。

### 予測が外れたところ

| 予測 | 実際 |
| --- | --- |
| 得点が 0〜1 に縮んだのはバランス値のせい | **測った方針のせい**だった。起きている親に撃ち続ける方針しか無く、再加点できていなかった |
| 寝入りばなの一撃を弱めれば独走は崩れる | **崩れなかった**（9 → 6）。1 点に 1 発で済み、札を引かないことが本体。規則と 5 値の組で崩した |
| TC-069 が緑なら REQ-056 は守られている | **破れていた。**独走する方針がテストに無かった（ADR-0023） |
| `scratch/` の計測は本番に影響しない | **影響した。**`src/Ten.Pure.csproj` を参照して Release ビルドしたら `src/Ten.Pure/obj/Release/` に生成物ができ、**Unity のコンパイルが二重定義で落ちた** |

### 仕組みの側で直したこと

| 直したこと | なぜ |
| --- | --- |
| **テストに方針を足したら、値を戻して赤くなることまで確かめた**（ADR-0023 の表） | 「通すために比較相手を足した」との区別は、**足した順番と戻したときの結果**でしか示せない |
| `scratch/balance/` は純粋層のソースを直接コンパイルする | `src/` の中に生成物を作らない。**`scratch/` は本番を import しないだけでなく、本番の置き場も汚さない** |
