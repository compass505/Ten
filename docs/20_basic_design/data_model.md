## 1. 3 つの塊に分ける

| 塊 | 寿命 | 壊れたときの被害 |
| --- | --- | --- |
| `Device` | 端末にずっと残る | チュートリアルをもう一度やる |
| `Today` | 日付が変わると捨てる | その日の最高成績が消える（REQ-033 が許容） |
| `Run` | プレイが終わると捨てる | 進行中のプレイをやり直す |

**分ける理由は、壊れたときに捨てる範囲を分けるため**（REQ-033）。
`Run` だけ壊れていたら `Today` は残す。

## 2. `Device`（端末に永続）

| 項目 | 型 | 要件 |
| --- | --- | --- |
| `tutorialDone` | 真偽 | REQ-034 |
| `schemaVersion` | 整数 | 保存形式の版。読めない版なら初期化する |
| `boardSpecVersion` | 整数 | 盤面仕様の版（REQ-040）。**書いた時点の版**を残し、起動時にアプリの版と比べる |

- `boardSpecVersion` がアプリの版と違えば、`Today` と `Run` を捨てる。
  **盤面の作り方が変わっているので、続きから遊ぶと別の盤面になる**
- チュートリアル専用盤面の版は別枠（[screens.md](screens.md) D-09）

## 3. `Today`（その日の記録）

| 項目 | 型 | 要件 |
| --- | --- | --- |
| `boardDate` | 日付（**正午 12:00 境界**） | REQ-019 / 022 |
| `playCount` | 整数 | その日の通算プレイ回数（REQ-031 / 048）。**放棄したプレイも数える**（REQ-037） |
| `best` | 下の表 or 無し | その日の最高成績（REQ-025） |

`best` の中身:

| 項目 | 要件 |
| --- | --- |
| `score` | 覚醒させた回数（REQ-023） |
| `playIndex` | 何回目のプレイか（REQ-031） |
| `endKind` | `dawn` / `fellAsleep` / `handEmpty`（REQ-054） |
| `commentary` | 実況テキスト 3 文以内（REQ-026） |

- **同点なら先に遊んだほうを残す**（REQ-025）。`score` が等しいとき `best` を更新しない
- `commentary` は生成結果を保存する。**再生成しない**（同じ入力列から作れるが、
  盤面仕様の版が変わると文が変わりうるため）
- 起動時に `boardDate` が今日と違えば、`Today` ごと捨てて作り直す

## 4. `Run`（進行中のプレイ）

REQ-032 / REQ-053 が名指ししているものに、[screens.md](screens.md) 4.3 の時計と通番を足したもの。
**ここに漏れがあると、中断復帰で REQ-020（同じ入力列 → 同じ状態列）が壊れる。**

| 群 | 項目 | 要件 |
| --- | --- | --- |
| 同一性 | `boardDate` / `playIndex` | REQ-036 / 048 |
| 時刻 | `tick`（0〜5400） | REQ-032。ゲーム内時刻はここから導出する |
| 赤ちゃん | `babyState`（`Open` / `Act` / `Closed`）/ `actKind` / `actRemain` / `vigor` | REQ-003 / 014 / 032 |
| 親 | `parentState`（`Sleep` / `Care` / `Settle` / `Grace` / `Up`）/ `arousal` / `careKind` / `careRemain` | REQ-032 / 049 |
| 慣れ | `habit[4]`（対処ごと） | REQ-029 |
| 時計 | `tIdle` / `tClosed` / `tSettle` / `tGrace` | screens.md 4.3 |
| 山札 | `hand[4]`（種類ごとの残枚数） | REQ-041 / 053 |
| 出来事 | `eventsFired`（発生済みの索引） | REQ-053 |
| 乱数の通番 | `pretendN`（寝たふりの回数）/ `dozeTick`（`doze_off` の刻み回数）/ `choiceN`（`parent_choice` の回数） | REQ-032 / ADR-0008 |
| 得点 | `score` / `scoredEdge`（加点済みかのエッジ） | REQ-052 |

- **`pretendN` は「引いた回数」であって「次に引く番号」ではない。**
  `fall_asleep` と `sleep_pretend` は**同じ tick に同じ通番**で引き、
  両方を引いた後に +1 する（[screens.md](screens.md) 4.3）
- **`scoredEdge` を保存しないと、復帰した tick でもう一度加点される**（REQ-052 のエッジ検出）
- `careRemain` / `actRemain` は tick 数。**実時間で持たない**

## 5. 保存しないもの

| 保存しない | 理由 |
| --- | --- |
| 首の向き | 表示層の値。状態列に影響しない（REQ-020 の対象外）。復帰時は正面から |
| 見た目の段階 | 状態から毎回導出する（`MOD-Display` は純関数） |
| 演出・アニメーションの進捗 | 同上。**`ST-P-Settle` は `tSettle` で進むので演出に依存しない**（D-07） |
| 過去の日の結果・履歴 | scope.md で「やらない」 |
| 乱数そのものの値 | 用途と通番から再計算できる（ADR-0008） |

**乱数の値を保存しないのに再現できるのは、`Hash(シード, 用途, 通番)` が純関数だから。**
保存するのは通番だけでよい。

## 6. 保存のタイミング

| いつ | 何を | 理由 |
| --- | --- | --- |
| `ST-N-Pause` に入った tick | `Run` | REQ-009 / 010。**Android はここから先、予告なくプロセスを破棄する** |
| 夜が終わった tick | `Today`（`best` の判定後）、`Run` を消す | REQ-025 |
| プレイを開始した tick | `Today.playCount` を +1、`Run` を作る | REQ-031 / 048 |
| プレイを放棄した時 | `Run` を消す（`playCount` はそのまま） | REQ-037 |
| チュートリアル完了 | `Device.tutorialDone` | REQ-034 |

- **定期保存はしない。**フォーカス喪失が唯一の確実な契機で、それ以外は書く理由が無い
- **原子的に書く**（`MOD-Storage`）: 一時ファイルに書き切ってから rename する。
  途中で落ちても、前の版が壊れない

## 7. 壊れていたときの扱い（REQ-033）

`SCR-Boot` が読む順に判定する。

| 壊れているもの | 捨てるもの | 行き先 |
| --- | --- | --- |
| `Run` だけ | `Run` | `SCR-Home`（その日の記録は残る） |
| `Today`（`Run` の有無を問わず） | `Today` + `Run` | `SCR-Recover` → `SCR-Home` |
| `Device` | すべて | `SCR-Recover` → `SCR-Tutorial` |
| `schemaVersion` が読めない / 未来の版 | すべて | `SCR-Recover` → `SCR-Tutorial` |
| `boardSpecVersion` がアプリと違う | `Today` + `Run` | `SCR-Home`（**破損ではないので `SCR-Recover` を通さない**） |

**「壊れている」の判定**: 読めない / 必須項目が無い / 範囲外の値が入っている
（[balance.md](balance.md) 2 節の範囲）/ 検査値が合わない。
**範囲チェックを入れるのは、部分的に壊れたデータで不変条件が破れるのを防ぐため。**

## 8. 決定論との関係（REQ-020 / NFR-004）

復元したあと、**同じ入力列を与えれば同じ状態列になる**ことがこの設計の合格条件。

- 4 節に挙げたものが揃っていれば、`tick` から先の計算は純粋層だけで閉じる
- **乱数は引き直さない。**通番を保存しているので、同じ用途・同じ通番から同じ値が出る
- **保存に含まれない値（首の向き・演出）は、状態列に一切影響してはいけない。**
  これは `MOD-Sim` が表示層を参照しないこと（[architecture.md](architecture.md) の依存方向）で
  機械的に保証する
- ハーネスのテストは「途中で保存 → 復元 → 続きを再生」した状態列が、
  中断しなかった場合と一致することを見る
