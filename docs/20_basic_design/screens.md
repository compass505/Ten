## 0. 2 階層に分ける

| 階層 | ID | 中身 | 担当 |
| --- | --- | --- | --- |
| 画面 | `SCR-Xxx` | アプリのどの面を見ているか。6 件 | `MOD-Shell` |
| 夜の状態 | `ST-x-Xxx` | `SCR-Night` の内側。**3 つの並行する状態機械** | `MOD-Sim` / `MOD-End` |

`ST-` の 2 文字目は所属する機械を表す（`B` = 赤ちゃん / `P` = 親 / `N` = 夜全体）。

**数値・ゲージの禁止（REQ-044）は `SCR-Night` の中だけに掛かる。**
`SCR-Home` / `SCR-Result` の得点・プレイ回数は数字で出す（REQ-023 / 031）。

## 4. 夜の内側（`SCR-Night`）

### 4.0 この設計で確定させたこと

出典は [ADR-0013](../10_requirements/decisions/ADR-0013-pretend-requires-closed-eyes.md)（Accepted）と
[ADR-0008](../10_requirements/decisions/ADR-0008-randomness-scope.md)。

> **D-01〜D-07 は 2026-09-06 に確定した**（ADR-0013 承認）。D-08〜D-10（2.1 節）は ADR-0013 に依存しない。

| ID | 決定 | 根拠 | 影響する要件 |
| --- | --- | --- | --- |
| D-01 | **`ST-B-Closed` の間にできるのは「目を開ける」だけ。**泣く / ぐずる / ばたつかせるは受け付けない | REQ-016「いつ目を開けるかを決める」が唯一の選択になる | **REQ-059 として起案した。**REQ-003 の本文は書き換えない |
| D-02 | **寝たふりの入口は閉眼。**`ST-B-Closed` が一定時間続いたときだけ、親は「寝た」と判断する | 閉眼中に情報が増えない構造でしか REQ-016 は成立しない | **REQ-015 の「一定時間何もしない」を「目を閉じて一定時間何もしない」と読む** |
| D-03 | **`t_idle` をリセットするのは覚醒行動（泣く / ぐずる / ばたつかせる）だけ。**眼の操作（閉じる / 開ける）はリセットしない | 目を閉じて即開けるのを繰り返して REQ-047 の寝落ちを永久回避する抜け道を塞ぐ。**REQ-003 の「行動」と `t_idle` の「何もしない」で語を分ける** | REQ-014 / 029 / 047 |
| D-04 | **寝たふりの判定は、`t_closed` が閾値に到達し、かつ親が `ST-P-Sleep` のときだけ。**`fall_asleep(n)` → `sleep_pretend(n)` の順に評価し、`n` を +1。**親が `ST-P-Sleep` でなければ判定せず、`n` も増やさない** | 判定できない親状態で乱数を消費すると、REQ-017 の成功率と以後の値がずれる | REQ-015 / 016 / 017 / 018 |
| D-05 | **寝落ちの乱数は 2 用途。**`fall_asleep` は寝たふりの判定 tick（通番 `n`）、**`doze_off`（用途を追加）**は無操作の刻み。**`doze_off` は `ST-P-Settle` / `ST-P-Grace` の間だけ停止する** | ADR-0008 の用途一覧に REQ-047 の用途が無い。停止区間を決めないと REQ-018 と REQ-047 が二重に走る | REQ-018 / 047 |
| D-06 | **境界は「着地したかどうか」の 1 点。**`ST-P-Settle`（抱き上げ〜着地）中の開眼は**気づかれて `ST-P-Care`**（山札 −1）。`ST-P-Grace`（着地後の猶予）中の開眼は**成功への手順**なので失敗にしない | 賭けに「早く開けすぎる」という負け筋を作る。同時に、成功手順を失敗と取り違えない | REQ-015 / 016 |
| D-07 | **`ST-P-Settle` の長さは固定 tick 数（`t_settle`）。**演出の終了で遷移させない。閉眼中に親が新しく対処を始めることもない | 演出終了を契機にすると、実フレームレート・中断・Animator の更新モードで状態列が変わる | NFR-004 / 005 / REQ-020。REQ-006 は「閉眼中は新しい対処が始まらない」で確定（残りは [ISS-18](../10_requirements/open_issues.md)） |

```
ST-B-Open ──目を閉じる──▶ ST-B-Closed （ここから先は何も見えない）
                              │
              t_closed が閾値に到達 ＆ 親が ST-P-Sleep
                              │
                   ┌──────────┴──────────┐
          fall_asleep(n) で寝る     寝ない → sleep_pretend(n)
                   │                      │
                   ▼              ┌───────┴───────┐
              ST-N-End         成功              失敗
             （寝落ち）           │                │
                          ST-P-Settle       何も起きない
                        （抱き上げ〜着地）  （成功と区別できない）
                        t_settle 固定 tick
                                 │
                    ┌────────────┴────────────┐
              途中で開眼                    着地
            （気づかれる）                    │
                    │                  ST-P-Grace（猶予）
              ST-P-Care                      │
              （山札 −1）        開眼して泣く │ ← ここだけが最大の一撃
                                             ▼
                                       ST-P-Up（+1 点）
```

**閉眼してから泣くまで、観測できるものは一切増えない。**
これが REQ-016（成否を事前に知らされないまま、いつ目を開けるかを決める）の成立条件。

### 4.1 赤ちゃん（プレイヤー）

| ID | 状態 | できること | 出口 |
| --- | --- | --- | --- |
| `ST-B-Open` | 目を開けている | 首を振る（ドラッグ）/ 行動を選ぶ | 覚醒行動 → `ST-B-Act` / 目を閉じる → `ST-B-Closed` / 寝落ち → `ST-N-End`（`doze_off`。REQ-047） |
| `ST-B-Act` | 覚醒行動の実行中（泣く / ぐずる / ばたつかせる） | **別の行動を受け付けない**（REQ-003）。首振りは受け付ける（REQ-038） | 行動が終わる → `ST-B-Open` |
| `ST-B-Closed` | 目を閉じている。**寝室の像を失う**（REQ-004）。窓の明るさだけ見える（REQ-008） | **目を開けることだけ**（D-01 / REQ-059） | 目を開ける → `ST-B-Open` / 寝落ち → `ST-N-End`（`fall_asleep` または `doze_off`） |

- 首振り（ドラッグ）は状態を変えない。`ST-B-Open` / `ST-B-Act` に対して直交する（REQ-038）
- **元気が尽きている間は覚醒行動を選べない**（REQ-014）。これは状態ではなく `ST-B-Open` の中の条件。
  何もしない間に元気は回復するため、行き止まりにならない（→ 5 節 C-04）
- `ST-B-Closed` では首を振れない（見えるものが無いため）
- `ST-B-Act` の間だけ `t_idle` が 0 に戻る。**寝落ちしない唯一の状態**
- **開眼して待つ / 閉眼して待つは別の行為で、どちらも一方的に優れない**（REQ-056）。
  開眼して待てば親の状態を読めるが**寝たふりは成立しない**。閉眼して待てば寝たふりを狙えるが
  何も見えず、`fall_asleep` と `doze_off` の両方にさらされる

### 4.2 親

| ID | 状態 | 内容 | 出口 |
| --- | --- | --- | --- |
| `ST-P-Sleep` | 寝ている（覚醒度は上限未満） | **寝たふりの判定が走る唯一の状態**（D-04） | 対処を出す → `ST-P-Care` / `sleep_pretend` が成功 → `ST-P-Settle` / 覚醒度が上限 → `ST-P-Up` |
| `ST-P-Care` | 対処中（トントン / ミルク / 抱っこ / オムツ替え）。**山札 −1** | **この間の赤ちゃんの行動は覚醒度を上げない**（REQ-049）。対処への慣れが付く（REQ-029） | 対処が終わる → `ST-P-Sleep` / 覚醒度が上限 → `ST-P-Up` |
| `ST-P-Settle` | 抱き上げて布団に置く。**赤ちゃんは盲目。**長さは固定 tick（`t_settle`。D-07） | 着地の瞬間は見えない | `t_settle` 満了（着地）→ `ST-P-Grace` / **途中で開眼 → `ST-P-Care`**（気づかれる。山札 −1） |
| `ST-P-Grace` | 着地後の猶予（REQ-015 の「置かれてから一定時間内」） | **開眼は失敗にしない**（D-06）。ここで泣いた場合だけ最大の上昇 | 泣く → 覚醒度に応じて `ST-P-Up` / `ST-P-Sleep`（4.5 の順 8） / `t_grace` 満了 → `ST-P-Sleep` |
| `ST-P-Up` | 完全に覚醒してベッドを出ている（**得点済み**）。**視界から消える**（部屋が空になり、部屋の電気が点く） | 加点は上限到達の瞬間に 1 回だけ（REQ-052）。**顔も手も見られないので覚醒度と次の対処が読めない** | 静かな時間が続く → `ST-P-Sleep`（REQ-030。覚醒度が定められた値まで下がる） |

- `ST-P-Sleep` → `ST-P-Care` の遅れは、山札の残量が少ないほど大きい（REQ-046）
- 山札が 0 のとき `ST-P-Care` には入れない。0 になった時点で夜が終わる（REQ-050）
- **`ST-P-Settle` / `ST-P-Grace` は山札を消費しない。**
  ただし**気づかれて `ST-P-Care` に落ちると 1 枚消費する**（早く開けすぎた代償が山札に出る）

### 4.2.1 視線と情報の対応（D-11）

**REQ-006 の 4 つは、同時には分からない。**首を向けた先のものだけが読める。
これが「一人称でなければ成立しない」（[ADR-0007](../10_requirements/decisions/ADR-0007-game-design.md)）の
実装上の意味になる。

| 見る先 | 分かること | 要件 |
| --- | --- | --- |
| 親の顔 | 親の覚醒度 | REQ-006 / 044 |
| 親の手 | **次に来る対処**（予告中）と、今している対処 | REQ-006 / 046 |
| 窓 | 残り時間 | REQ-008 |
| 天井（どれでもない） | 何も分からない | — |
| **親がいない**（`ST-P-Up` / 部屋を出ている） | **顔も手も読めない。**残り時間だけが分かる | REQ-030 |
| — | **赤ちゃんの元気は常に分かる**（自分の体なので視線に依存しない） | REQ-006 |

- 首の可動範囲（REQ-002）に対して、**3 つの対象は同時に視界へ入らない位置に置く。**
  プロトタイプの実測では **寝室の窓** −55〜−41° / 親の顔 −1〜39° / 親の手 29〜55°
- **初期視線は天井**（何も分からない）。見ることが選択になる
- 出来事「親が寝返りを打つ」（REQ-055）の間は、**顔を見ても覚醒度が読めない**
- 目を閉じている間は視線に関係なく何も分からない（[ADR-0014](../10_requirements/decisions/ADR-0014-closed-eyes-information.md)）

### 4.3 時計と判定

**「何もしていない」の意味を 1 つに固定する**（D-03）。要件ごとに別の意味にしない。
**REQ-003 の「行動」（4 つ）と、`t_idle` をリセットする「覚醒行動」（3 つ）は別の集合。**

| 時計 | 進む条件 | 0 に戻る条件 | 使う要件 |
| --- | --- | --- | --- |
| `t_idle` | `ST-B-Act` **以外**の間（眼の操作では止まらない） | `ST-B-Act` に入った tick | REQ-014（元気回復）/ REQ-029（慣れが戻る）/ REQ-047（寝落ち） |
| `t_closed` | `ST-B-Closed` の間 | 目を開けた tick | REQ-015（寝たふりの成立）/ REQ-018 |
| `t_settle` | `ST-P-Settle` の間。**固定 tick 数で満了**（D-07） | `ST-P-Settle` に入った tick | REQ-020 / NFR-004 / 005 |
| `t_grace` | `ST-P-Grace` の間 | `ST-P-Grace` に入った tick | REQ-015（最大の一撃の猶予） |

乱数を引く点は 3 つだけ。用途と通番は
[ADR-0008](../10_requirements/decisions/ADR-0008-randomness-scope.md) の一覧に従う。

| 判定 | 引く tick | 用途 | 通番 | 要件 |
| --- | --- | --- | --- | --- |
| 寝たふり中の寝落ち | `t_closed` が閾値到達 **かつ** 親が `ST-P-Sleep` | `fall_asleep` | その夜で何回目の寝たふりか（`n`） | REQ-018 |
| 寝たふりの成否 | 同じ tick（寝落ちしなかった場合のみ評価） | `sleep_pretend` | 同上（**同じ `n`**） | REQ-015 / 016 / 017 |
| 待機中の寝落ち | `t_idle` が閾値を超えている間、定められた刻みごと | **`doze_off`（用途を追加。D-05）** | その夜で何回目の刻み判定か | REQ-047 |

- **`fall_asleep` と `sleep_pretend` は同じ tick に同じ `n` で引く。**
  `n` の +1 は両方を引いた**後**に行う（1 回目の寝たふりはどちらも通番 1）
- **親が `ST-P-Sleep` でないとき、判定は行わず `n` も増やさず、`t_closed` もリセットしない。**
  親が `ST-P-Sleep` に戻った tick で、閾値を超えたままなら判定する
- 用途別ストリームなので**引く順序は結果に影響しない。**評価順だけを固定する
- **`doze_off` は `ST-P-Settle` / `ST-P-Grace` の間は走らない**（D-05）。
  それ以外は開眼・閉眼を問わず走るため、**閉眼を刻んで寝落ちを回避する経路は無い**
- 保存対象（REQ-032 / 053）: `n`・`doze_off` の刻み回数・親の状態・4 本の時計・
  進行中の対処と残り。**中断復帰で引き直すと REQ-020 が壊れる** → `data_model.md`

| `ST-N-Pause` | 中断。**ゲーム内時間が止まる**（REQ-009）。画面消灯抑止も止める | 表示は直前の状態のまま | 復帰 → `ST-N-Run`（同じ状態から）/ 放棄 → `SCR-Home`（T-11）/ プロセス破棄 → 次回 `SCR-Boot` から復元（REQ-010） |

### 4.5 1 tick の処理順（REQ-039）

同じ tick に複数の事象が重なったときの順序を一意に決める。**この順序が決定論の前提になる。**

| 順 | 処理 | 担当 | 根拠 |
| --- | --- | --- | --- |
| 1 | **入力を 1 tick 1 件に正規化して適用する。**同じ tick に複数の入力が割り付いたら先着 1 件だけを採り、残りは**捨てる**（キューに残さない） | `MOD-Input` | REQ-020 / 038 / 039 |
| 2 | その時刻の出来事を発生させる（山札・赤ちゃん・親・視界） | `MOD-Sim` | REQ-043 / 055 |
| 3 | **覚醒度に依存しない**親の遷移（`Care` の開始 / 終了、`Settle` → `Grace`、`Settle` 中の開眼 → `Care`、`Grace` の満了）。`Grace` で泣いた場合は**最大上昇を予約するだけ** | `MOD-Sim` | REQ-013 / 046 / 049 / D-06 |
| 3.5 | **REQ-049 の適用範囲。**「親が対処を返すまでの間」は `ST-P-Care` 中だけでなく、**対処が決まってから返るまでの遅れ（REQ-046）も含む。**この間の覚醒行動は覚醒度を上げない | `MOD-Sim` | REQ-046 / 049 |
| 4 | 時計を進める（`t_idle` / `t_closed` / `t_settle` / `t_grace`） | `MOD-Sim` | D-03 / D-07 |
| 5 | **寝たふりの判定**（`t_closed` 閾値到達 かつ 親が `ST-P-Sleep` なら `fall_asleep(n)` → `sleep_pretend(n)` → `n` を +1） | `MOD-Sim` | REQ-015〜018 |
| 6 | **待機中の寝落ちの判定**（`Settle` / `Grace` 中は停止。5 を引いた tick はスキップ） | `MOD-Sim` | REQ-047 |
| 7 | 状態値の更新（覚醒度・元気・慣れ・ゲーム内時刻）。**順 3 で予約した最大上昇もここで適用する** | `MOD-Sim` | REQ-012 / 014 / 015 / 029 |
| 8 | **覚醒度に依存する親の遷移**（上限到達 → `ST-P-Up` / 定められた値まで低下 → `ST-P-Sleep`） | `MOD-Sim` | REQ-030 / 052 |
| 9 | **得点の判定**（上限到達のエッジ検出） | `MOD-Score` | REQ-051 / 052 |
| 10 | **終了の判定**（夜明け → 寝落ち → 山札切れ の順） | `MOD-End` | REQ-007 / 018 / 042 / 047 / 050 / 051 |
| 11 | 見た目の段階への写像 | `MOD-Display` | REQ-044 / 045 / 058 |

- **順 1 が順 3 より先**なので、`t_grace` の満了と同じ tick に泣いたときは**入力が勝つ**
- **順 1 が 1 件しか採らない**ので、「開眼」と「泣く」は必ず別の tick になる。
  閉眼中の泣く入力は捨てられ、**副作用も残さない**（REQ-059 の判定条件）
- **順 3 と順 8 を分けた**のは、`Grace` で泣いた tick の順 3 ではまだ覚醒度が更新されておらず、
  `ST-P-Up` と `ST-P-Sleep` のどちらへ行くか決められないため
- **順 9 が順 10 より先**であることは REQ-051 から決まる。
  [architecture.md](architecture.md) の `MOD-End` → `MOD-Score` の依存方向と一致する
- 順 10 の内側（夜明け → 寝落ち → 山札切れ）も固定する。同 tick で複数成立したときは
  この順で先に成立したものを終わり方として記録する（REQ-054 の表示が一意に決まる）

### 経緯（Codex レビュー 2 周）

**採用案は A → F → A と往復した。**理由は
[ADR-0013](../10_requirements/decisions/ADR-0013-pretend-requires-closed-eyes.md) の
「検討の経緯」に書いてある。要点だけ:

- 1 周目で「A の選択肢比較が閉じていない」と指摘され、案 F に差し替えた
- 2 周目で **案 F が REQ-016（成否を事前に知らされない）に正面から違反する**と分かり、A に戻した
- **1 周目の指摘のうち A に効いていたのは形式と運用の 3 件だけ**で、構造への反論ではなかった

2 周のレビューで塞いだもの:

| 指摘 | 対応 |
| --- | --- |
| ADR だけで確定要件の適用範囲を狭めている（ADR-0010 は REQ-058 を発番している） | **REQ-059 を発番**（D-01）。2026-09-06 に ADR-0013 とともに確定 |
| 閉眼中に REQ-006 を満たせない | D-07 で主要ループを塞ぎ、残りを **ISS-18** として起票 |
| 実機でしか判定できない条件を確定前に検証できない | **O-09** として最優先で残した |
| `sleep_pretend` / `fall_asleep` の判定が tick 処理順に無い | 4.3 / 4.5 に追加（D-04） |
| `ST-B-Open` の出口に寝落ちが無い | 4.1 に追加。用途 `doze_off` を足した（D-05） |
| 閉眼を刻めば REQ-047 を永久回避できる | `t_idle` を眼の操作でリセットしない（D-03） |
| 「何もしない」が要件ごとに別の意味 | 時計 4 本と「覚醒行動 / 眼の操作」の語彙分離（4.3） |
| `ST-P-Settle` 中に目を開けたときの親の遷移が無い | `ST-P-Care` へ落とす。**境界は「着地したか」の 1 点**（D-06） |
| `ST-P-Settle` の終了が演出にぶら下がり、決定論が壊れる | **`t_settle` を追加し固定 tick で満了**（D-07） |
| `Grace` の成功処理が処理順と矛盾（順 3 で遷移できない） | **順 3 は予約のみ。順 8 で覚醒度に基づく親遷移**（4.5） |
| `Grace` 満了と泣く入力の同 tick 競合が未定義 | **入力が勝つ**（4.5 の但し書き） |
| `fall_asleep` と `doze_off` が重複して走る | **`doze_off` を `Settle` / `Grace` 中は停止**（D-05） |
| 判定できない親状態で乱数を消費する | **判定は `ST-P-Sleep` のときだけ。`n` も増やさない**（D-04） |
| `n` の通番が `sleep_pretend` と `fall_asleep` でずれる | **同じ tick に同じ `n` で引き、+1 は両方の後**（4.3） |
| 同 tick の「開眼＋泣く」で結果が実装依存 | **1 tick 1 入力に正規化。捨てた入力は副作用を残さない**（4.5） |
| 「賭けに負けた 3 経路」が全経路でない | **6 経路の表**に置き換えた（5 節 C-10） |
| Proposed の ADR から REQ-059 だけ確定扱いになっていた | REQ-059 / D-01〜D-07 を**暫定**と明示 |
