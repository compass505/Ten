## 0. 2 階層に分ける

| 階層 | ID | 中身 | 担当 |
| --- | --- | --- | --- |
| 画面 | `SCR-Xxx` | アプリのどの面を見ているか。6 件 | `MOD-Shell` |
| 夜の状態 | `ST-x-Xxx` | `SCR-Night` の内側。**3 つの並行する状態機械** | `MOD-Sim` / `MOD-End` |

`ST-` の 2 文字目は所属する機械を表す（`B` = 赤ちゃん / `P` = 親 / `N` = 夜全体）。
3 つは同時に 1 つずつ状態を持つ。

**数値・ゲージの禁止（REQ-044）は `SCR-Night` の中だけに掛かる。**
`SCR-Home` / `SCR-Result` の得点・プレイ回数は数字で出す（REQ-023 / 031）。

## 3. Android の戻る操作

戻るボタンの行き先を決めていない画面は行き止まりになる。全画面について定める。

| 画面 | 戻る操作 | 備考 |
| --- | --- | --- |
| `SCR-Boot` | 受け付けない | 通過するだけ |
| `SCR-Tutorial` | 受け付けない | 完了以外の出口を作らない（REQ-034） |
| `SCR-Home` | アプリを終了する | 確認を出さない |
| `SCR-Night` | **中断する**（`ST-N-Pause` へ）。夜からは直接出ない | REQ-009 と同じ扱い |
| `SCR-Result` | `SCR-Home` へ（T-12 と同じ） | 最高成績の判定は必ず通る |
| `SCR-Recover` | 受け付けない | 初期化しないと先に進めない |

## 4. 夜の内側（`SCR-Night`）

### 4.0 この設計で確定させたこと

| ID | 決定 | 根拠 | 影響する要件 |
| --- | --- | --- | --- |
| D-01 | **`ST-B-Closed` の間にできるのは「目を開ける」だけ。**泣く / ぐずる / ばたつかせるは受け付けない | ユーザー判断 2026-09-02。ADR-0007 の核（いつ目を開けるかが賭け）と [game_overview.md](../10_requirements/game_overview.md) 4 節（置かれた直後に**目を開けて泣く**） | REQ-003 の「行動を選んで実行できる」は、目を開けている間に限る |
| D-02 | **`ST-P-Settle`（親が寝たと判断して抱き上げる）に入るのは、`ST-B-Closed` が一定時間続いたときだけ。**目を開けたまま待っても成立しない | ユーザー判断 2026-09-02。目を閉じる（＝寝室の像を失う）代償を払った者だけが最大の一撃を狙える | **REQ-015 の「一定時間何もしない」を「目を閉じて一定時間何もしない」と読む。**REQ-015 の本文は書き換えない（→ 6 節 O-06） |

D-01 / D-02 により、寝たふりの経路は 1 本に固定される。

```
ST-B-Open ──目を閉じる──▶ ST-B-Closed ──（一定時間）──▶ 親が ST-P-Settle
                              │                              │
                       寝落ち │                              ▼ 布団に置く
                              ▼                        （ここから一定時間が勝負）
                          ST-N-End                            │
                                                    目を開ける │
                              ST-B-Open ◀────────────────────┘ → 泣く（最大の一撃）
```

### 4.1 赤ちゃん（プレイヤー）

| ID | 状態 | できること | 出口 |
| --- | --- | --- | --- |
| `ST-B-Open` | 目を開けている | 首を振る（ドラッグ）/ 行動を選ぶ | 行動 → `ST-B-Act` / 目を閉じる → `ST-B-Closed` |
| `ST-B-Act` | 行動の実行中（泣く / ぐずる / ばたつかせる） | **別の行動を受け付けない**（REQ-003）。首振りは受け付ける（REQ-038） | 行動が終わる → `ST-B-Open` |
| `ST-B-Closed` | 目を閉じている。**寝室の像を失う**（REQ-004）。窓の明るさだけ見える（REQ-008） | **目を開けることだけ。**泣く / ぐずる / ばたつかせるは受け付けない（D-01） | 目を開ける → `ST-B-Open` / 寝落ち → `ST-N-End`（REQ-018） |

- 首振り（ドラッグ）は状態を変えない。`ST-B-Open` / `ST-B-Act` に対して直交する（REQ-038）
- **元気が尽きている間は行動を選べない**（REQ-014）。これは状態ではなく `ST-B-Open` の中の条件。
  何もしない間に元気は回復するため、行き止まりにならない（→ 5 節 C-04）
- `ST-B-Closed` では首を振れない（見えるものが無いため）

### 4.2 親

| ID | 状態 | 内容 | 出口 |
| --- | --- | --- | --- |
| `ST-P-Sleep` | 寝ている（覚醒度は上限未満） | 赤ちゃんの行動で覚醒度が上がる | 対処を出す → `ST-P-Care` / 寝たと判断 → `ST-P-Settle` / 覚醒度が上限 → `ST-P-Up` |
| `ST-P-Care` | 対処中（トントン / ミルク / 抱っこ / オムツ替え）。**山札 −1** | **この間の赤ちゃんの行動は覚醒度を上げない**（REQ-049）。対処への慣れが付く（REQ-029） | 対処が終わる → `ST-P-Sleep` / 覚醒度が上限 → `ST-P-Up` |
| `ST-P-Settle` | 赤ちゃんが寝たと判断し、抱き上げて布団に置く | **入るのは `ST-B-Closed` が一定時間続いたときだけ**（D-02）。置かれた後の一定時間が寝たふりの勝負どころ（REQ-015） | 置き終える → `ST-P-Sleep` |
| `ST-P-Up` | 完全に覚醒してベッドを出ている（**得点済み**） | 加点は上限到達の瞬間に 1 回だけ（REQ-052） | 静かな時間が続く → `ST-P-Sleep`（REQ-030。覚醒度が定められた値まで下がる） |

- `ST-P-Sleep` → `ST-P-Care` の遅れは、山札の残量が少ないほど大きい（REQ-046）
- 山札が 0 のとき `ST-P-Care` には入れない。0 になった時点で夜が終わる（REQ-050）
- `ST-P-Up` は「山札を切らない」状態。ここで待つと `ST-P-Sleep` に戻る（REQ-030）

### 4.3 夜全体

| ID | 状態 | 内容 | 出口 |
| --- | --- | --- | --- |
| `ST-N-Run` | 進行中。tick が進む | — | フォーカス喪失 / 戻る操作 → `ST-N-Pause` / 終了条件 → `ST-N-End` |
| `ST-N-Pause` | 中断。**ゲーム内時間が止まる**（REQ-009）。画面消灯抑止も止める | 表示は直前の状態のまま | 復帰 → `ST-N-Run`（同じ状態から）/ 放棄 → `SCR-Home`（T-11）/ プロセス破棄 → 次回 `SCR-Boot` から復元（REQ-010） |
| `ST-N-End` | 終了。3 通りのいずれか | 得点と終わり方が確定している | → `SCR-Result`（T-10） |

終了条件（`ST-N-End` への入り口）:

| 終わり方 | 契機 | 要件 |
| --- | --- | --- |
| 夜明け | ゲーム内 6:00 に到達 | REQ-007 |
| 寝落ち | `ST-B-Closed` 中 / 行動していない時間が続いたとき | REQ-018 / 047 |
| 山札切れ | 山札が 0 になった（対処による消費 / 出来事による減少を問わない） | REQ-042 / 050 |

### 4.4 1 tick の処理順（REQ-039）

同じ tick に複数の事象が重なったときの順序を一意に決める。**この順序が決定論の前提になる。**

| 順 | 処理 | 担当 | 根拠 |
| --- | --- | --- | --- |
| 1 | その tick に割り付いた入力を適用する（`ST-B-*` の遷移） | `MOD-Input` → `MOD-Sim` | REQ-020 / 038 |
| 2 | その時刻の出来事を発生させる（山札・赤ちゃん・親・視界） | `MOD-Sim` | REQ-043 / 055 |
| 3 | 親の対処の解決（`ST-P-Care` の開始 / 終了、山札の消費） | `MOD-Sim` | REQ-013 / 046 / 049 |
| 4 | 状態値の更新（覚醒度・元気・慣れ・ゲーム内時刻） | `MOD-Sim` | REQ-012 / 014 / 029 |
| 5 | **得点の判定**（上限到達のエッジ検出） | `MOD-Score` | REQ-051 / 052 |
| 6 | **終了の判定**（夜明け → 寝落ち → 山札切れ の順） | `MOD-End` | REQ-007 / 018 / 042 / 047 / 050 / 051 |
| 7 | 見た目の段階への写像 | `MOD-Display` | REQ-044 / 045 / 058 |

- **5 が 6 より先**であることは REQ-051（最後の 1 枚の得点は終了判定より先）から決まる。
  [architecture.md](architecture.md) の `MOD-End` → `MOD-Score` の依存方向と一致する
- 6 の内側の順序（夜明け → 寝落ち → 山札切れ）も固定する。同 tick で複数成立したときは
  先に成立したものを終わり方として記録する（REQ-054 の表示が一意に決まるため）

## 6. 決めきれていないこと

**ここが埋まるまでこの設計は確定ではない。**数値（`ST-B-Act` の長さ・寝たふりの必要時間・
段階の粗さ・圧縮率）は [architecture.md](architecture.md) の「未着手」と同じ扱いで、
[ISS-10](../10_requirements/open_issues.md) と衝突する場所。

| ID | 論点 | 影響 | 状態 |
| --- | --- | --- | --- |
| O-02 | 日付をまたいで再開したプレイの成績の扱い | REQ-036（開始時の盤面のまま最後まで遊べる）× REQ-025（その日の最高成績）× 保存は当日分のみ。完走できるが成績の帰属先が決まっていない | **未確定**。遷移そのものは閉じている（どちらでも `SCR-Home` に戻る） |
| O-04 | `SCR-Tutorial` が使う盤面 | その日の盤面を使うとプレイ回数（REQ-031 / 048）に影響する。専用の固定盤面なら影響しない | **未確定**（本書は「消費しない」とだけ決めた） |
| O-05 | `SCR-Home` の「続きから」を自動化するか（`SCR-Boot` から直接 `SCR-Night` へ） | 中断が日常的（REQ-009 / ISU-15）なので手数を減らしたいが、放棄（REQ-037）の入り口が要る | **未確定**（本書は明示選択で閉じた） |
| O-06 | D-02 は REQ-015 の「何もしない」を狭めている。ADR-0010 が REQ-008 の「正確に」を読み替えたのと同じ形 | 実装後に覆すと、夜の核となる周回とテストがまとめて作り直しになる | **ADR を起こすべき**（未着手） |
