## 1. パラメータ（7 軸）

**各軸は「量」ではなく「起こし方の質」で分ける。**
これを守らないと、全部が「たくさん起こしたか」の 1 軸に潰れる。

| 軸 | 親から見た意味 | 主に何で増えるか |
| --- | --- | --- |
| **いらだち** | 音の量 | 強く泣く / **連続して**泣く |
| **疲労** | 体を動かされた量 | **重い対処**（ミルク・オムツ替え）を引き出す |
| **徒労** | 報われなさ | **寝たふりを通す**（寝たと信じて置いたのに） |
| **寝不足** | 睡眠の断片化 | **寝入りばなを潰す** / 熟睡中に起こす |
| **不安** | 分からなさ | **対処の直後に再び泣く** / 慣れているのに収まらない |
| **翻弄** | 空振り | **対処の最中に**割り込む |
| **いとおしさ** | 救い | **元気があるのに**静かにしている / トントンで収まる |

**「いとおしさ」は必須。**6 軸すべてがマイナスだと、診断が
「どれだけ親を痛めつけたか」の報告書になる。
[setting.md](setting.md) 1 節が「**親を悪者にしない。負けても嫌な気持ちにならないこと**」を
決めている以上、救いの軸が要る。

### 乗り方

- **1 つの行動が 1〜3 個の軸に乗る。**乗る先は**親の状態と、自分の直前の行動**で変わる
- **3 つ目はランダムで乗る。**用途 `Diagnosis` の乱数を使う。
  **実行時の乱数を使わない**（REQ-020 / 021 が壊れる）
- 具体値は [balance.md](balance.md)。ADR-0012 によりテストの期待値に書かない

### 実測（24 シード × 7 方針 = 168 サンプル）

| 軸 | レンジ | 最大になる方針 |
| --- | --- | --- |
| いらだち | 0〜67% | ぐずり型 |
| 疲労 | 0〜46% | ばたつき型 |
| 徒労 | 0〜57% | 寝たふり型 |
| 寝不足 | 0〜32% | 狙い型 |
| 不安 | 0〜30% | 連打 |
| 翻弄 | 0〜33% | 割り込み型 |
| いとおしさ | 0〜77% | 静か型 |

**相関 0.6 を超える組は「いらだち↔いとおしさ −0.64」の 1 組だけ。**
負の相関（うるさくすればいとおしさは減る）なので意味論的に正しく、冗長な軸は無い。

## 2. 診断の選び方

```
1. 7 軸の値を合計で割り、割合ベクトルにする（夜の長さと激しさに依存させない）
2. カタログの各診断が持つプロファイル（7 次元）とコサイン類似度を取る
3. 最も近いものを選ぶ。同点はカタログの並び順で先を採る（決定論）
4. 合計値の大きさで「濃さ」の修飾語を付ける
```

- **合計が閾値未満なら `DX-41`（何も起きなかった夜）を固定で返す。**
  ほぼ何もしなかった夜は割合ベクトルが定義できない
- **最大軸だけで決めない。**実測で 7 方針中 3 つが「いらだち」最大になり、
  狙い型の特徴（寝不足 22%）も割り込み型の特徴（翻弄 20%）も拾えなかった。
  **特徴はベクトルの形に出る**

| 濃さ | 条件 | 付く言葉 |
| --- | --- | --- |
| 薄 | 合計が小さい | 「うっすら」 |
| 並 | — | （無し） |
| 濃 | 合計が大きい | 「どっぷり」 |

閾値は [balance.md](balance.md)。

## 3. 文言の書き方

| 守ること | 理由 |
| --- | --- |
| **親を責めない。**主語は「今夜」であって「あなた」ではない | [setting.md](setting.md) 1 節。親は疲れていて、でも毎回ちゃんと来る |
| **負けても嫌な気持ちにならない。**得点 0 の診断こそ優しく | 遊ぶのは寝かしつけた直後の本人 |
| **あるあるで笑わせる。**皮肉と自虐にしない | ADR-0006。笑いの質は共感 |
| **盤面の答えを含めない** | REQ-028 |
| **名前 + 2〜4 文。**一行では足りない（本人判断 2026-09-06） | **その夜を思い出せるだけの具体が要る。**一行だと「あるある」の輪郭しか出ず、笑いが立ち上がらない |
| それでも**貼れる長さ**に収める | 見せ合いに使われる（ADR-0006） |

## 4. カタログ（50 件）

> **文言は未確定。**下の「一行」は**プロファイルの意図を示すための仮置き**で、
> 3 節が定めた長さ（2〜4 文）を満たしていない。**書き直しが未着手**
> （[handoff.md](../00_process/handoff.md) H-02）。**プロファイルの側は確定扱いでよい。**

## 5. 決めていないこと

| ID | 論点 |
| --- | --- |
| DG-01 | カタログを 50 件で足りるとするか。**1 日 1 回として 50 日で一周**する計算。増やすなら文言を足すだけで済む |
| DG-02 | 「濃さ」の閾値。夜の長さによって合計が変わるので、tick で割って正規化するか |
| DG-03 | 同じ診断が連日出たときに避けるか（**避けると決定論が壊れる**ので、避けないのが既定） |
| DG-04 | 診断を結果テキストの何行目に置くか。実況 3 文（REQ-026）との並び |
