# ADR-0005: 書く側と検める側を分け、検める側に別モデルファミリを使う

- ステータス: **Accepted**（2026-08-31 承認）
- 日付: 2026-08-31
- 関連: [ADR-0003](ADR-0003-improvement-loop.md) 段階4「別文脈のレビュー」

## 背景

[ADR-0003](ADR-0003-improvement-loop.md) で実行ループの停止条件として
「別視点のレビュー」を段階4に置いたが、**誰が検めるか**を決めていなかった。

素直にやると Claude が書いたものを Claude が検めることになる。これは機能しない。
生成時に置いた前提を、レビュー時も正しいものとして通してしまうため。
同一ファミリのモデルは失敗の仕方まで相関するので、
サブエージェントに分けて文脈を切っても、チェックとしては弱い。

この環境では Codex CLI（別ファミリ）を Claude から呼び出せる。

## 選択肢

| 案 | 利点 | 欠点 |
| --- | --- | --- |
| A. Claude が自分で見直す | 追加コストゼロ | 自己採点。前提の誤りが素通りする |
| B. Claude のサブエージェント（文脈だけ分ける） | 文脈汚染は防げる。設定が軽い | 同一ファミリなので失敗が相関する |
| C. Codex に検めさせる（別ファミリ） | 失敗の相関が切れる。反対側の立場を明示的に取らせられる | 外部サービスに中身が出る。指摘の質にばらつき |
| D. 人間が全部検める | 最も確実 | 1人開発では持続しない。ボトルネックになる |

## 決定

**C を基本とし、対象によって B・D と使い分ける。**

決め手は「**失敗の仕方が相関しないこと**」。文脈を分けても、同じモデルファミリなら
同じ見落とし方をする。相関を切るには、書いた側と別のファミリを使うしかない。

| 対象 | 書く | 検める | 手段 |
| --- | --- | --- | --- |
| ADR・要件・設計・テスト項目 | Claude | **Codex（読み取り専用）** | `codex-critic` スキル |
| ドキュメントの規約準拠・DoD の穴 | Claude | Claude（別文脈） | `doc-auditor` エージェント |
| 実装コード（フェーズ5） | **Codex** | Claude | ADR-0001 確定後に定義 |
| 機械的な検証 | — | コマンド | `tools/check_docs.py` |

原則:

1. **Codex に確定前レビューをさせるとき `--write` を付けない。** 反論を受け取るのが目的
2. **「レビューして」と投げない。** 役割を反対尋問として固定する。でないと同意しか返らない
3. **Codex の指摘を鵜呑みにしない。** 粗を探せと言われたレビュアは健全なものにも粗を報告する。
   A（覆す）/ B（記述を直す）/ C（却下）に仕分け、**却下も理由つきで報告する**
4. **Claude が自分で Accepted にしない。** 最終判断は人間

## 結果

- 自己採点の経路が塞がれた。引き換えに、確定前に1ステップ増えて遅くなる
- **外部サービス（Codex）にドキュメントとコードが出る。**
  初回は必ずユーザーに確認する運用にした
- Codex はこのプロジェクトの規約（ADR-0002 の決定論4条件、ADR-0004 のドキュメント方針）を
  知らないので、それらと衝突する提案が一定数混ざる。仕分けのコストは残る
- 実装フェーズの委譲（Codex が書き、Claude が検める）は方向だけ決めて、
  具体（モデル・effort・規約検証の grep）は ADR-0001 の後に回した

## この決定が崩れる条件

- Codex の指摘が3回連続で全て分類 C（却下）だったとき → 費用対効果が無い
- 仕分けのコストが、自分で見直すコストを上回ったとき
- 外部にドキュメントを出せない事情ができたとき → B と D に切り替える
