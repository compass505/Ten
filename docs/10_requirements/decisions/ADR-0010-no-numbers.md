# ADR-0010: 状態を数値で表示せず、粗い固定段階の見た目で表す

- ステータス: **Accepted**（2026-09-02 承認）
- 日付: 2026-09-02
- 関連: ISS-16 / ISU-46 / ISU-55〜59 / ISU-67 /
  [ADR-0007](ADR-0007-game-design.md) / [ADR-0011](ADR-0011-per-play-randomness.md) /
  REQ-006 / REQ-008 / REQ-044 / REQ-045 / REQ-058

## 背景

REQ-006 は「親の覚醒度・赤ちゃんの元気・残り時間・親が今している対処を
画面から知ることができる」としか書いておらず、**表示の形式を縛っていない。**
このままだと、覚醒度をゲージで、元気を数値で出す設計が要件を満たしてしまう。

親の山札（REQ-041）が入ったことで、**残量をどう伝えるか**が問題になった。
枚数を出せば数回で読み切られ、何も出さなければ理不尽になる。

**今決める必要があるのは、フェーズ 2（基本設計）で画面を設計する直前だからである。**

### 初稿からの変更（2026-09-02）

**初稿は「見た目の変化 + 日付シードから決まるずれ」を採用していた。**
[Codex レビュー](../../50_review/issues.md)（ISU-46 / 54 / 57 / 66 / 67）で
次を指摘され、ユーザー判断により差し替えた。

1. **選択肢の比較が成立していなかった。**案 B（対応固定）を「数回で割れる」として
   退けたが、**段階を粗くすれば、規則を理解しても内部値は確定しない**
2. ずれには上限・単調性・端点の保証が無く、**満杯の山札が「残りわずか」に見える実装も
   要件を満たしてしまう**。それは不完全情報ではなく、観測が判断材料にならない状態
3. **ずれは ADR-0007 の核から導けない。**ADR-0007 の核は「目を閉じた間に情報を失う」ことで、
   **寝たふり中はそもそも寝室が見えない**（ISU-67）
4. Must なのに合格条件を書けない（ISU-57）。用途 `display_bias` の通番も定義できない（ISU-66）

## 選択肢

| 案 | 利点 | 欠点 |
| --- | --- | --- |
| A. 数値・ゲージで表示する | 実装が最も簡単。デバッグと検証が容易 | **読み切れてしまう。**ジレンマ 1 が計算問題になり、ADR-0007 の決め手を自分で捨てる |
| **B'. 粗い固定段階で表す（採用）** | 対応が固定なので**テストできる**（この値ならこの見た目）。段階が粗いので「終盤に入った」は分かるが「あと何枚」は分からない。**学習が報われる**（規則を覚えるほど読めるが、区間より細かくは読めない）。視覚的な冗長化を足せる | 段階の粗さの設定次第で、粗すぎれば判断材料にならず、細かすぎれば数えられる |
| B. 細かい固定段階で表す | 情報量が多く、迷いが少ない | 段階が細かいほど枚数を数えられ、実質 A になる |
| C. 見た目で表しつつ、詳細表示で正確な値も見られる | どちらのプレイヤーにも合う | 見られる以上は全員が見る。実質 A になる |
| D. 見た目 + シード由来のずれ（**初稿の採用案。取り下げ**） | 日をまたぐ攻略表を防げる | **当日中は 1 回目で割れる**（ISU-44）。テストできない。端点を保証できない。ADR-0007 から導けない |

## 決定

**B' を採用する。**

決め手は、**「なんとなく分かるが、はっきりとは分からない」を作っているのは
乱数ではなく段階の粗さだと分かったこと。**
粗い固定段階なら、規則を完全に理解しても「残り 1〜3 枚のどれか」までしか分からない。
そのうえで対応が固定なので、テストでき、端点を保証でき、視覚的な冗長化も足せる。
D が持っていた利点（読み切れなさ）は B' がそのまま持ち、欠点だけが消える。

**REQ-008 の「残り時間を正確に知ることができる」は、以後
「定められた粗さの区間を識別できる」と読む**（→ REQ-058）。
REQ-006 の「知ることができる」も同じく区間の識別を指す。
REQ-008 / REQ-006 の本文は書き換えず、この差し替えはこの ADR で行う。

## 結果

固定されるもの:

- **画面に数値・ゲージを置かない。**状態は寝室の中の見た目で表す
  （親の顔・手・姿勢、窓の明るさ、部屋の照明）
- **見た目の段階と実際の値の対応は固定**であり、段階は粗い。
  段階の中のどこにいるかは分からない
- **端点は正確に表す。**山札が空、覚醒度が上限、夜が明ける直前は、区間ではなく確定して分かる
- **明度差だけに依存しない。**輪郭・模様・姿勢・動きの周期による冗長化を行う（ISU-56）。
  アイコンを一律には禁止しない
- 用途 `display_bias` は**廃止**する
- 開発中は別途デバッグ表示が要る（本番ビルドから外す）

諦めたもの:

- **正確な情報に基づく最適化の楽しさ。**プレイヤーは常に区間で判断する
- **一部のアクセシビリティ。**冗長化はするが、音もバイブも使えないため、
  視覚以外の経路は無い。**対象 2 人での識別試験に通らなければ、この決定は破綻する**
- **「同じ見た目を見ているから公平」とは言えない**（ISU-55）。
  同じ段階を出していることは対称性の証明であって、
  2 人が同じ情報を受け取った証明ではない。表示性能と識別能力の差は残る

覆すコスト:

- **B' → A（数値表示を足す）は、テスト作成フェーズより前なら安い。**
  それ以降は、画面テスト・チュートリアル・視認性テストの期待値が変わるため、
  **ISS-10（テスト書き換え禁止）と衝突する**（ISU-58）。可逆性を承認理由に使わない

## この決定が崩れる条件

- **対象 2 人が段階を識別できないと判明したとき**（REQ-044 の判定方法で確かめる）
- 段階が粗すぎて判断材料にならない、または細かすぎて数えられると判明したとき
- 見た目の作り分け（顔・手・姿勢・照明の複数段階）が、2〜3 週間を壊すと判明したとき
