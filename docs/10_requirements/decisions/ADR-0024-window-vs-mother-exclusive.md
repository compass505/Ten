# ADR-0024: 視界の排他を「窓 ⇔ 母」に定め、TC-122 を対象端末の縦画面で測る

- ステータス: Accepted（2026-09-14。委任 — handoff.md H-08）
- 日付: 2026-09-14
- 関連: REQ-006 / D-11（screens.md 4.2.1）/ MOD-View V-3 / TC-122 / setting.md 3 節 /
  ADR-0007 / ADR-0019 / ADR-0020（テスト側を直した前例）/ handoff.md H-10

## 背景

2026-09-14 に母 r56-approved と寝室 room-r1 を**実寸で**取り込んだ（presentation.md 2.0）。
対象端末の縦画面（1080 × 2400、水平 35° = 垂直 70°）で首を振って測ると、

| yaw（pitch 0） | 視界に入る対象 |
| --- | --- |
| −55°〜−35° | 窓 |
| −30°〜0° | なし（天井） |
| 5°〜15° | 母の顔 |
| **20°〜55°** | **母の顔と手** |

**窓と母が同時に入る角度は無い。母の顔と手は同時に入る。**

食い違いは 3 か所にあった。

1. **D-11 / V-3 / TC-122 の文言**は「**3 対象**は同時に視界へ入らない」
2. **e2e の TC-122 のアサーション**は「視界に入る対象は **1 つまで**」（文言より厳しい）
3. **setting.md 3 節の表**は、顔 −1〜39° / 手 29〜55° で**もともと重なっている**

さらに、**e2e の TC-122 は取り込み後も緑だった。**batchmode の画面が縦長でないため、
縦の画角が狭く、母の顔（pitch 約 +32°）が視界の外に外れていただけで、**対象端末の見え方を測っていない。**
「測っていないのに緑」（DeviceNfrTests の注意書き）と同じ事故である。

## 選択肢

| 案 | 利点 | 欠点 |
| --- | --- | --- |
| A. **窓 ⇔ 母を排他とし、顔と手の同時表示は許す**。TC-122 を縦画面で測る | 文言（3 対象が同時に入らない）と setting.md の表に合う。モデルを作り直さない | 「顔を見るか、手を見るか」の選択は無くなる。選択は「**時間（窓）を見るか、母を見るか**」になる |
| B. Codex に手の静止位置を顔から離させる（1 つまでを守る） | 3 択の選択が残る | 座ったまま隣でトントンする姿勢（ADR-0021）と両立しにくい。r56-approved の合格（ADR-0019）をやり直す。**1 日を超える** |
| C. 画角を狭める | モデルを触らない | 承認済みの垂直 70° を崩す。狭いと酔いやすく（NFR-009）、母の姿がほとんど入らない |

## 決定

**案 A。**

- **D-11 / V-3 の意味**: 「窓と母（顔・手）は同時に視界へ入らない」。3 対象が同時に入らないことはここから従う
- **TC-122 の判定**: 対象端末の縦画面（NFR-001 で固定した向き。1080 × 2400）の縦横比で首の可動範囲を走査し、
  **窓と、母の顔または手が同時に入る角度が存在しない**
- **測り方**: 画面の縦横比に任せず、`RoomRig.VisibleTargets(aspect)` に縦横比を渡して測る

決め手は 2 つ。
**D-11 の文言（3 対象）と setting.md の表（顔と手が重なる）はもともと A を指していた**こと。
**1 つまでの判定は、テストだけが要件より厳しく書いていた**（ADR-0020 と同じ「判定の作り方の事故」）こと。

## 結果

- `unity/Assets/Tests/ViewE2ETests.cs` の TC-122 と `ScreenProbe` を直した。**検証したい性質（窓と母が同時に見えない）は残し、判定を縦画面で行う形にした**
- `docs/40_test/cases/TC-view-shell.md` の TC-122、MOD-View V-3、screens.md 4.2.1、setting.md 3 節の角度を実測値にした
- harness の TC-122（`GazeRule.HasOverlap`）は区間の性質を見るテストで、値はテスト用の配置なので変えない
