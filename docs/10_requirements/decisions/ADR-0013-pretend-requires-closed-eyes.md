# ADR-0013: 寝たふりは「目を閉じている間」にだけ成立させる

## 背景

REQ-015 は寝たふりをこう書いている。

> プレイヤーは、**一定時間何もしない**ことで親に「寝た」と判断させ、
> 布団に置かれてから一定時間内に泣くことで、その夜の他のどの行動よりも大きい
> 覚醒度の上昇を得ることができる

**「何もしない」の中身が定義されていない。**目を閉じている必要があるのか、
目を開けたまま行動しなければよいのかが、この一文からは決まらない。

REQ-003 も同じ穴を持っている。4 つの行動（泣く / ぐずる / 手足をばたつかせる / 目を閉じる）を
選べるとしか書いておらず、**目を閉じている間に他の行動を選べるかを排除していない。**

**今決める必要があるのは、フェーズ 2（基本設計）の
[screens.md](../../20_basic_design/screens.md) が書けないからである。**
親が抱き上げる状態（`ST-P-Settle`）の入口条件と、目を閉じた状態（`ST-B-Closed`）の出口が
決まらないと、夜の状態遷移が閉じない（フェーズ 2 の DoD）。

### 検討の経緯（2 周の Codex レビュー）

**この ADR は一度 A → F → A と往復している。記録として残す。**

| 周 | 起きたこと |
| --- | --- |
| 初稿 | 案 A（閉眼を寝たふりの入口にする）を採用 |
| 1 周目 | 「選択肢の比較が閉じていない。入口条件と報酬条件を別軸にすれば REQ-015 を読み替えずに済む」と指摘され、**案 F に差し替えた** |
| 2 周目 | 案 F に「決定を覆すべき」3 件。**F は REQ-016 に正面から違反していた**（下記）。案 A に戻した |

**案 F が壊れていた理由:**

1. **REQ-016 との衝突。**F は `sleep_pretend` が成功したときだけ親の予兆（`ST-P-Reach`）を
   見せる設計だったため、**予兆の有無が成否の完全な通知**になっていた。
   REQ-016 は「**成否を事前に知らされないまま**、いつ目を開けるかを決める」と書いている
2. **支配戦略。**同じ時刻から待つなら成功率も寝落ちも元気回復も同一で、
   開眼側だけが予兆を観測できる。「開眼して待つ」が「閉眼して待つ」を弱支配する（REQ-056）
3. **決め手が仕様上存在しなかった。**盲目区間に着地を知らせる観測可能な変化が無い

**1 周目の指摘のうち、案 A に本当に効いていたのは形式と運用の 3 件だけだった。**
いずれもこの版で手当てしてある（REQ-059 の発番 / ISS-18 の起票 / 実機プロトタイプ）。
**構造そのものへの反論ではなかった。**

## 選択肢

| 案 | 入口条件 | 報酬条件 | 利点 | 欠点 |
| --- | --- | --- | --- | --- |
| **A. 閉眼を入口にする（採用）** | **閉眼が一定時間続く** | 置かれた後の猶予に開眼して泣く | **REQ-016 をそのまま満たす。**閉眼中に情報が一切増えないので、「成否を知らないまま、いつ目を開けるかを決める」が構造として成立する。閉眼と開眼のどちらで待つかに、それぞれ別の得と損がある（REQ-056） | 盲目でいる時間が長い。REQ-015 の読み替えが要る。**「どれだけ盲目でいられるか」が面白いかは実機でしか判定できない** |
| B. 文面通り。報酬条件を足さない | 無操作が一定時間続く（開眼可） | 置かれた後に泣く | 読み替えが一切要らない | **目を閉じる理由が無くなる。**ADR-0007 の核が空洞になる |
| C. どちらでも成立し、閉眼のほうが成功率が高い | 無操作（閉眼で確率上昇） | 置かれた後に泣く | 両方の遊び方が残る | 成功率が 2 次元になり REQ-017 の減衰と掛かる。賭けの構造が曖昧 |
| F. 入口は文面通り、盲目区間を「抱き上げ〜着地」に置く（**2 周目で棄却**） | 無操作（開眼可） | 予兆を見て閉眼し、着地まで継続 | REQ-015 を読み替えずに済む | **REQ-016 に違反する。**予兆が成否の通知になる。開眼待ちが弱支配する。盲目区間に判断材料が無い |
| D. REQ-015 の本文を書き換える（形式の案） | — | — | 要件と設計が一致し、二重管理が起きない | **既存 ID の意味を後から変えない**（[workflow.md](../../00_process/workflow.md)）に反する |
| E. 新規要件だけで解決し、ADR にしない（形式の案） | — | — | 要件が要件の場所にある | 後戻りコストが 1 日を超える判断の**理由が残らない** |

## 決定

**A を採用する。**形式は **ADR + 新規要件（REQ-059）**とし、
[ADR-0010](ADR-0010-no-numbers.md) が REQ-058 を発番したのと同じ形に揃える。

決め手は、**REQ-016（成否を事前に知らされないまま、いつ目を開けるかを決める）が
成立するのは、閉眼中に情報が一切増えない構造だけだったこと。**
F のように閉眼の前後で観測できるものが増えると、その観測が成否の通知になる。
A は閉眼した瞬間に世界が閉じるので、賭けの対象が「あとどれだけ盲目でいられるか」だけになる。

## 結果

固定されるもの:

- **REQ-015 の「一定時間何もしない」は「目を閉じた状態が一定時間続く」と読む。**
  目を開けたまま待っても、親は「寝た」と判断しない
- **REQ-059 を新規発番する**（目を閉じている間は、目を開けること以外の行動を実行できない）。
  REQ-003 の本文は書き換えない
- **`ST-P-Settle`（抱き上げ〜着地）の間に目を開けると、親が気づいて通常の抱っこ
  （`ST-P-Care`。山札 −1）になる。**`ST-P-Grace`（着地後の猶予）の間の開眼は成功への手順であり、
  ここは失敗にしない。**境界は「着地したかどうか」の 1 点**
- **`ST-P-Settle` の長さは固定 tick 数で決める**（`t_settle`）。演出の終了で遷移させない
  （実フレームレートに状態列が依存すると NFR-004 / 005 が壊れる）
- **寝たふりの判定は、親が `ST-P-Sleep` のときにだけ行う。**
  `ST-P-Care` / `ST-P-Up` の間に閉眼の閾値へ達しても判定せず、試行回数 `n` も増やさない
- **待機中の寝落ち（`doze_off`）は `ST-P-Settle` / `ST-P-Grace` の間だけ停止する。**
  それ以外は開眼・閉眼を問わず走る（REQ-018 と REQ-047 の判定が重ならない）
- **「行動」の語を 2 つに分ける。**`t_idle` をリセットするのは
  **覚醒行動**（泣く / ぐずる / ばたつかせる）だけで、**眼の操作**（目を閉じる / 開ける）は
  リセットしない。REQ-003 が列挙する 4 つは、入力の排他については従来どおり「行動」として扱う
- 乱数は [ADR-0008](ADR-0008-randomness-scope.md) の用途一覧に従う。
  `fall_asleep` と `sleep_pretend` は**同じ tick に同じ通番 `n` で**引く。
  REQ-047 には**用途 `doze_off` を追加する**（用途を足すのは ADR-0008 が安全と認めている）

諦めたもの:

- **視界を保ったまま最大の一撃を狙う遊び方。**親の様子を見ながら寝たふりは仕掛けられない
- **要件の文面だけで仕様が分かる状態。**REQ-015 の読み替えと REQ-059 を読まないと分からない。
  [ADR-0010](ADR-0010-no-numbers.md) と同じ負債をもう 1 件積む
- **待ち方が 1 種類だったときの単純さ。**「目を開けて待つ」と「目を閉じて待つ」が別の行為になり、
  テストの入力列が 2 系統になる
- **`ST-P-Settle` を演出の都合で伸縮させる自由。**固定 tick に縛られる
- **盲目時間の長さを短くして苦痛を減らす、という逃げ道。**
  短くすると賭けが消える。**この 2 つを同時に満たす保証は無い**（→ 下の「崩れる条件」）

覆すコスト:

- 現時点では [screens.md](../../20_basic_design/screens.md)・REQ-059・この ADR のみ
- 実装後に覆すと、夜の核となる周回（`ST-B-*` / `ST-P-*` の遷移）と、
  それに紐づくテストがまとめて作り直しになる

## この決定が崩れる条件

- 実機で、**何も見えないまま待つ時間が苦痛**だと分かったとき。
  **これがこの決定の最大の弱点で、紙の上では判定できない**（→ screens.md O-09）
- 盲目時間を短くすると賭けが消え、長くすると苦痛になる、という**両立不能**が確認されたとき
- 寝たふりが 1 回も成立しないまま終わるプレイが多発したとき（入口が狭すぎる）
- 対象の 2 人が「目を閉じないと寝たふりにならない」を、
  チュートリアル（REQ-034）でも理解できなかったとき
- [ISS-18](../open_issues.md)（閉眼中に親の対処を知る手段が無い）が REQ-006 違反として
  解決不能と判定されたとき
- [ADR-0007](ADR-0007-game-design.md) が覆され、「目を閉じる」が核でなくなったとき
