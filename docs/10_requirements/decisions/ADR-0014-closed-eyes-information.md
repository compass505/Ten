# ADR-0014: REQ-006 の「知ることができる」は、目を開けている間について言う

- ステータス: **Accepted**（2026-09-06 承認）
- 日付: 2026-09-04
- 関連: REQ-004 / 006 / 008 / 044 / 058 / [ISS-18](../open_issues.md) /
  [ADR-0010](ADR-0010-no-numbers.md)（REQ-008 の読み替えの先例） /
  [ADR-0013](ADR-0013-pretend-requires-closed-eyes.md)（閉眼が主要ループに入る） /
  [screens.md](../../20_basic_design/screens.md) D-07

## 背景

2 つの Must 要件が正面から衝突している。

> REQ-004: プレイヤーは、目を閉じている間、**寝室の像を失った状態**のまま
> ゲームを進めることができる

> REQ-006: プレイヤーは、音とバイブレーションを一切使わない状態で、
> 親の覚醒度・赤ちゃんの元気・残り時間・**親が今している対処**を画面から知ることができる

REQ-006 は閉眼中の例外を書いていない。音もバイブも無く（scope.md）、
閉眼中は寝室の像も無いのだから、**「親が今している対処」を知る経路が原理的に存在しない。**

この衝突は要件確定時（2026-09-02）から存在していたが、
[ADR-0013](ADR-0013-pretend-requires-closed-eyes.md) が閉眼を寝たふりの入口にしたことで、
**演出上の一瞬ではなく主要ループで毎回発生する**ようになった（Codex レビュー 2026-09-04 の指摘）。

**今決める必要があるのは、このままだと基本設計が Must 違反を含んだまま
フェーズ 3 に進むからである。**テスト作成フェーズに入ると、
REQ-006 のテストが「閉眼中も対処を知れること」を要求して落ち続ける。

## 選択肢

| 案 | 利点 | 欠点 |
| --- | --- | --- |
| **A. REQ-006 の「知ることができる」を、目を開けている間についての要件と読む（採用）** | **REQ-008 に既に同じ書き分けがある**（「目を開けている間は…目を閉じている間は窓の明るさによって時間帯だけを」）。REQ-006 だけが例外を持たないのは書き漏れとみなせる。[ADR-0010](ADR-0010-no-numbers.md) が REQ-008 を読み替えた形をそのまま使える | 要件の文面と設計の読みがまた 1 件ずれる。REQ-006 を読んだだけでは分からない |
| B. 閉眼中も対処が分かる視覚経路を作る（まぶた越しの明暗・振動の視覚化など） | REQ-006 を文面のまま満たせる | **REQ-004 と衝突する。**「寝室の像を失う」と言いながら像を出すことになる。[ADR-0007](ADR-0007-game-design.md) の核（目を閉じれば分からなくなる）を壊す |
| C. 閉眼中は親が対処を一切しないことにする | 情報が無くても矛盾しない | 閉眼前から続いている対処を途中で消すことになり、不自然。**山札の消費が入力で止められる**抜け道になる |
| D. REQ-006 の本文を書き換える | 要件と設計が一致する | **既存 ID の意味を後から変えない**（[workflow.md](../../00_process/workflow.md)）に反する |

## 決定

**A を採用する。**

決め手は、**REQ-008 が同じ 4 つの状態のうち「残り時間」について
既に開眼時と閉眼時を書き分けており、REQ-006 との差が意図ではなく書き漏れだと読めること。**
REQ-008 は「目を開けている間は残りのゲーム内時間を正確に知ることができ、
目を閉じている間は窓の明るさによって時間帯だけを知ることができる」と書いている。
REQ-006 だけを閉眼中にも適用すると、同じ文書の中で矛盾する。

**REQ-006 の本文は書き換えない。**読み替えをこの ADR に置く
（[ADR-0010](ADR-0010-no-numbers.md) / [ADR-0013](ADR-0013-pretend-requires-closed-eyes.md) と同じ形）。

## 結果

固定されるもの:

- **REQ-006 の 4 つ（親の覚醒度・赤ちゃんの元気・残り時間・親が今している対処）は、
  目を開けている間に知ることができればよい。**閉眼中は窓の明るさだけ（REQ-008）
- **閉眼中に新しい対処が始まることはない**（[screens.md](../../20_basic_design/screens.md) D-07）。
  親は「寝た」と判断しているため `ST-P-Care` に入らない
- したがって**閉眼中に失われるのは、閉眼前から続いていた対処が
  いつ終わったかという情報だけ**になる。これは失われるのではなく**遅延する**
  （目を開けた瞬間に現在の対処が分かる）
- **目を開けた直後の 1 tick で、4 つすべてが現在値として読める。**
  復帰時に段階の表示を遅延させたり、アニメーションで補間したりしない
  （`MOD-Display` は状態から毎回導出する純関数）

諦めたもの:

- **要件の文面だけで仕様が分かる状態。**REQ-006 / REQ-008 / REQ-015 / REQ-044 の 4 件が、
  それぞれ別の ADR で読み替えられている状態になる。
  **要件を読む人は ADR-0010 / 0013 / 0014 を先に読む必要がある**
- 閉眼中に「まだトントンされている」と分かる安心感。閉眼は完全な断絶になる

覆すコスト:

- 現時点ではドキュメントのみ
- テスト作成フェーズ以降に B へ移すと、閉眼中の表示テストが新規に必要になる

## この決定が崩れる条件

- 対象の 2 人が、目を開けた瞬間に 4 つを読み取れないと分かったとき
  （段階が粗すぎる / 復帰時の認知負荷が高い）
- 閉眼中の断絶が「理不尽」と感じられ、`ST-B-Closed` に入ること自体が避けられたとき
- [ADR-0013](ADR-0013-pretend-requires-closed-eyes.md) が覆され、閉眼が主要ループから外れたとき
  （その場合、この衝突は演出上の一瞬に戻り、決め直す価値が下がる）
