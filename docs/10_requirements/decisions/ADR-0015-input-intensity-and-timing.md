# ADR-0015: 行動の入力を「強度」と「タイミング」の 2 軸にする

- ステータス: **Accepted**（2026-09-06 承認）
- 日付: 2026-09-05
- 関連: REQ-002 / 003 / 012 / 056 / **REQ-060 / 061（この ADR で起案）** / [ISS-19](../open_issues.md) /
  [ADR-0007](ADR-0007-game-design.md)（一人称） / [ADR-0009](ADR-0009-time-structure.md)（連続時間） /
  [balance.md](../../20_basic_design/balance.md) 13 節（実測）

## 背景

REQ-003 は「行動を選んで実行できる」としか書いていない。
実装すると**行動は固定長のボタン 1 押し**になり、次の 2 つが空洞になった。

1. **[ADR-0009](ADR-0009-time-structure.md) が連続時間を選んだ意味が無い。**
   入力が離散的な 1 押しである限り、ターン制でも同じことができる
2. **[ADR-0007](ADR-0007-game-design.md) が一人称を選んだ意味が薄い。**
   首を振ることに情報の選択（D-11）は与えたが、**行動の側に空間もタイミングも無い**

**ユーザー判定 2026-09-05**:
「これだと何回押すかになっている。リアルタイム制の意味も 3D の意味も薄い」。

**今決める必要があるのは、テスト作成フェーズに入る直前だからである。**
入力の形が決まらないと `TickInput` が確定せず、
[MOD-Input](../../30_detailed_design/MOD-Input.md) / [MOD-Sim](../../30_detailed_design/MOD-Sim.md) の
テストが書けない。

## 選択肢

| 案 | 中身 | 利点 | 欠点 |
| --- | --- | --- | --- |
| A. 現状維持 | 1 押し = 固定効果 | 要件を触らない。実装が最も軽い | **連続時間である必然性が無い。**測定でも「何回押すか」に収束した |
| B. 長押しだけ | 押している長さで強度が決まる | 連続時間が効く。実装が軽い | **実測で最弱（2.88）。**溜めるほど得なら常に最大が正解になり、判断が消える |
| C. 寝入りばなだけ | 親が寝入る瞬間に当てると効果が跳ねる | タイミングが効く。一人称（顔を見る）が効く | 1 押しのままなので「合わせる」操作が薄い。反射だけになる |
| **D. 両方（採用）** | 長押しで強度、かつ寝入りばなに当てると 2.5 倍 | **実測で最強（4.58、連打比 +33%）。**溜めることに代償があるので「どこで離すか」が判断になる。予兆は顔を見ていないと分からないので一人称が効く | 要件が 2 件増える。操作の説明が要る（REQ-034 の負荷が上がる） |
| E. 別の軸（連打速度 / リズム合わせ） | テンポで強度を出す | 音無しでもリズムは伝わる | **無音・暗所で正確なリズムを提示できない。**REQ-044 の視覚だけで拍を伝えるのは難しい |

## 決定

**D を採用する。**

決め手は、**測定で「片方だけでは連続時間の必然性が出ない」と出たこと。**
長押し単体は最弱（2.88）で、常に最大まで溜めるのが正解になり判断が消える。
寝入りばなと組み合わせて初めて連打（3.42）を上回った（4.58）。
**2 軸が噛み合ったときだけ、「どこで離すか」が毎回の判断になる。**

## 結果

固定されるもの:

- **REQ-060 / REQ-061 を起案する。**REQ-002 / 003 の本文は書き換えない
- **溜めることには代償を付ける**（これが無いと「常に最大」が正解になる）。
  元気の消費が強度に対して加速する / 満タンで持ち続けると元気が減る /
  対処が始まると溜めが飛ぶ / 強く出すほど親が対処を出してくる
- **背中スイッチ（`ST-P-Grace` 中の泣き）は溜めない。押した時点で最大強度**として発火する。
  猶予は 1 秒しかなく、最大まで溜めるのに 3.5 秒かかるため、**溜めを要求すると
  「その夜のどの行動よりも大きい上昇」（REQ-015）が最弱の強度でしか撃てなくなる。**
  置かれた瞬間の泣きは反射なので、溜めが要らないのは筋も通る
  （プロトタイプの測定で発見。[balance.md](../../20_basic_design/balance.md) 15 節）
- **寝入りばなには予兆を付ける**（予兆が無いと溜めが間に合わない）。
  予兆は**親の顔を見ていないと分からない**（[screens.md](../../20_basic_design/screens.md) D-11 と噛み合う）
- 倍率は**掃引で決めた 2.5**。2.0 だと腕の差が 0.25 しか出ず、
  3.5 だと連打の 2 倍以上になって外す人に厳しすぎる
- 数値は [balance.md](../../20_basic_design/balance.md) 13 節。ADR-0012 によりテストの期待値に書かない

諦めたもの:

- **1 押し = 1 行動という単純さ。**入力に「押している間」という状態が増え、
  `TickInput` が「その tick に押された」ではなく「その tick に押されている」になる
- **チュートリアルの軽さ。**教えることが 3 つ（覚醒度・元気・寝たふり）から増える。
  REQ-034 の「操作しながら知る」の負荷が上がる
- **片手・親指だけ（REQ-005）の余裕。**押しっぱなしの最中に首を振る操作が重なる。
  **同時接触は要求しないが、指の移動は増える**
- 実装の軽さ。溜めの状態（`BabyPhase.Charging`）と、その中断経路が増える

覆すコスト:

- 現時点では `scratch/mvp/` と 詳細設計の 2 箇所（[MOD-Input](../../30_detailed_design/MOD-Input.md) INP-01 /
  [MOD-Sim](../../30_detailed_design/MOD-Sim.md) SIM-01 / 02）
- **テスト作成フェーズ以降に A へ戻すと、入力列の記法とハーネスの再生系が作り直しになる**

## この決定が崩れる条件

- 実機で、**押しっぱなしが片手・親指で辛い**と分かったとき（REQ-005 と衝突する）
- 予兆（呼吸が深くなる）が暗所で見えず、寝入りばなに合わせられないとき
- チュートリアル（REQ-034）で 2 軸を伝えきれないとき
- 腕の差（+33%）が、対象の 2 人にとって**大きすぎる / 小さすぎる**と分かったとき
- [ADR-0009](ADR-0009-time-structure.md) が覆され、ターン制に戻ったとき（**この ADR は無意味になる**）
