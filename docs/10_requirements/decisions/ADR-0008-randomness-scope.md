# ADR-0008: 乱数を「用途別の独立ストリーム」とし、寝たふり等の判定にも使う

- ステータス: **Accepted**（2026-09-02 承認）
- 日付: 2026-09-02
- 関連: ISU-14 / ISU-19 / ISU-20 / ISS-06 / ISS-10 /

  [調査: M-2 のゲーム性](../research/game_mechanic_4.md) 6 節 /

## 背景

[ADR-0007](ADR-0007-game-design.md) の確定事項 5 は
「乱数は**盤面の生成にのみ使い、勝敗の決定には使わない**」と書いている。
一方、そのゲーム性を成立させた [game_mechanic_4.md](../research/game_mechanic_4.md) 6 節は
「シードで決まるもの：… **寝たふりの成功判定に使う乱数列**」と書いている。

**採用した決定と、その根拠になった調査が、逆のことを言っている**（ISU-14）。

**今決める必要があるのは、要件（REQ-xxx）に「同じ盤面」の範囲を書く段になったからである。**
どちらを採るかで「夫婦が同じ日に同じものを遊んでいる」の意味が変わり、
[ADR-0002](ADR-0002-test-harness.md) のハーネスが何を再現するのかも変わる。

### 初稿からの変更（2026-09-02）

**この ADR の初稿は「シードから 1 本の乱数列を作り、消費順に使う」を採用していた。**
[Codex レビュー](../../50_review/issues.md)（ISU-19 / ISU-20）で次の 2 点を指摘され、
ユーザー判断により採用案を差し替えた。

1. 初稿の決め手「同時に満たせるのが A だけ」は**偽**だった。用途別ストリームという
   未検討の案が、同じ要求を消費順序への依存なしに満たす
2. 1 本列は**変更耐性を壊す**。判定を 1 つ足す・減らす・呼び出し順を直すだけで
   その日以降の全結果が変わり、**ISS-10（実装フェーズでのテスト書き換え禁止）と直撃する**

## 選択肢

| 案 | 利点 | 欠点 |
| --- | --- | --- |
| **A'. 用途別の独立ストリーム（採用）**<br>`Hash(シード, 用途, 通番)` で必要な時に値を作る | **変更耐性がある。**新しい出来事や判定を足しても既存の用途の値が動かない。ISS-10 との衝突面積が小さい。**比較が公平**（「その夜 1 回目の寝たふり」は夫婦とも同じ値を引く）。テストで任意の状況を狙って再現できる | **用途の一覧を仕様として持つ必要がある**（用途を足すのは安全だが、用途名や通番の意味を変えると壊れる）。ハッシュを自前で持つ |
| A. シードから 1 本の乱数列を作り、消費順に使う | 実装が最も単純。「同じ盤面＝同じ乱数列」と説明が直感的。選択で消費位置がずれる＝運の引き方まで変わる | **変更耐性がほぼ無い**（ISU-20）。テストがゴールデン値に寄り、落ちた原因が乱数のずれかロジックの破損か区別できない。同じ「1 回目の寝たふり」でも、それまでの判定回数が違えば別の値を引く |
| B. 判定に乱数を一切使わない | テストの期待値が最も安定する。結果差が純粋に選択差になる | **寝たふりが賭けでなくなる。**緊張が「親の内部状態が見えないこと」だけに依存する |
| C. 親の手の「種類」だけシード乱数、成否は決定論 | ADR-0007 の文言をそのまま守れる | 成否が読めるため、結局 B と同じ問題が起きる。「一部だけ乱数」の境界を仕様で切り続けるコストが乗る |
| D. 実行時の乱数（端末の乱数源）を使う | 実装が最も簡単 | [ADR-0002](ADR-0002-test-harness.md) が成立しない。夫婦の比較も成立しない。**検討に値しない** |

## 決定

**A' を採用する。**

決め手は、**賭け・再現性・比較可能性という 3 つの要求を満たしたうえで、
ISS-10（テスト書き換え禁止とバランス調整の衝突）の被害範囲を実装前に縮められるのが
A' だけだったこと。**
A も 3 つの要求は満たすが、乱数の消費順序に全結果がぶら下がるため、
バランス調整のたびに「テストを書き換えるか、調整を諦めるか」の二択が発生する。

ADR-0007 確定事項 5 の文言は、以後
**「実行時の非決定な乱数（システム時刻・端末の乱数源・並列実行順）を使わない」**
と読む。この差し替えは ADR-0007 本文を書き換えず、この ADR で行う。

### 用途の一覧（ISU-27）

「寝たふり**等**の判定」の「等」を、以下に固定する。**ここに無いものに乱数を使わない。**

| 用途 | 通番の意味 |
| --- | --- |
| `parent_initial` | 親の初期覚醒度・寝不足度。通番なし（その日 1 回） |
| `parent_hand` | 親の手札の並び。通番＝配る順 |
| `night_event` | その夜に起きる出来事。通番＝出来事の順 |
| `sleep_pretend` | 寝たふりの成否。通番＝**その夜で何回目の寝たふりか** |
| `fall_asleep` | 寝たふり中に本当に寝てしまうか。通番＝同上 |
| `parent_choice` | 親がどの対処を選ぶか。通番＝その夜で何回目の対処か |

用途を後から**足す**のは安全（既存の値が動かない）。
用途名を変える・通番の意味を変えるのは**盤面仕様の版を上げる**（→ REQ-040）。

## 結果

固定されるもの:

- **「同じ盤面」＝同じ日付 → 同じシード → 用途と通番が同じなら同じ値。**
  プレイヤーの選択が変わっても、「その夜 1 回目の寝たふり」が引く値は変わらない
- 乱数の**アルゴリズム（ハッシュ）と用途一覧を仕様として固定する**必要が生じる。
  Unity / .NET 標準の乱数はバージョン間・実行環境間の再現を保証しないため、
  **実装をこちらで持つハッシュが要る**（→ ISS-06 の入力）
- テストの期待値は「シード + 用途 + 通番 + 入力列 → 結果」の形になる。
  **狙った状況（例: 1 回目の寝たふりが失敗する日）を指定して作れる**

諦めたもの:

- **「選択によって運の引き方まで変わる」という緊張。**
  同じ回数目の寝たふりは、いつ実行しても同じ値を引く。
  賭けが残るのは「**何回目にやるか**」「**いつ目を開けるか**」が選択だからであり、
  値そのものの不確実性ではなくなる
- 「1 本の乱数列」という一言で済む説明。用途一覧を仕様として維持する手間が乗る

覆すコスト:

- 現時点ではドキュメントのみ
- **テスト作成フェーズ以降に B へ移すと、乱数に依存した期待値が全滅する**

## この決定が崩れる条件

- 用途一覧の維持が破綻したとき（用途が 20 を超える、通番の意味が状況で変わる等）
- 「同じ回数目は同じ値」が読まれ、寝たふりの賭けが成立しないと判明したとき
  （その場合は通番に**そこまでの経過時間の粗い量子**を混ぜる案が次点になる）
- 自前のハッシュを持つコストが、2〜3 週間の見積もりを壊すと判明したとき
- 「運で負けた」感が強く、夫婦の見せ合いが煽りにしかならないと判明したとき
