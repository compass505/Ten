# スコープ

> 暫定。ゲームの中身が未定のため、確定していない。要件 ID の発番はまだしない。
> 2026-09-01 に方向を C'-1（夫婦で笑う共感ゲーム）へ変更したことに伴い全面改訂。

## やる（暫定）

- 寝かしつけ後、片手だけで遊べるゲーム
- 夫婦それぞれが遊び、**結果を見せ合って笑える**こと
- 共有は既存の手段（LINE 等）に貼るだけで成立させる
- 暗所・無音・いつでも中断できる前提で設計する
- 同じシードと入力列から同じ結果になる（[ADR-0002](decisions/ADR-0002-test-harness.md)）

## やらない（明示的にスコープ外）

- **「問題を解く」形式（クイズ・パズル等の正解があるもの）。**
  ユーザー判断 2026-09-01。正解があるゲームは面白みに欠け、笑いを作る構造として弱い
- **育児情報の提供。** P-5 を解く方向は 2026-09-01 に見送った。
  情報を入れると chocolate-covered broccoli になる（→ [research/game_direction.md](research/game_direction.md) 3 節）
- **医療的な判断・診断。** 情報を扱わないため、そもそも入り込む余地を作らない
- **サーバー・アカウント・リアルタイム通信。** Wordle 方式で成立させる。
  2〜3 週間に収めるための最大の判断
- **育児記録。** ぴよログが記録・家族共有・食材アドバイスまで実装済み
- **写真・動画の撮影と共有。** みてね で既に満たされている
- **音声・BGM を前提とした演出。** 寝かしつけ後は音を出せない
- **iOS 対応。** 本人の端末は Android（配偶者の端末は**未確認**）
- **端末の時計操作への対策。** 通信を持たない以上、信頼できる現在日時を取得できない。
  時計を戻せば過去の盤面を遊べてしまうが、防がない（REQ-022 / ISU-29）
- **過去の日の結果の閲覧・履歴。** 保存するのは当日分のみ（REQ-032 / ISU-43）
- **画面の向きの切り替え・複数解像度への最適化。** 対象端末を 1 台に固定する（NFR-001 / ISU-C3）

「やらない」を書かない要件定義は必ず膨らむ。迷ったらここに書いて外す。
