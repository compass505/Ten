# 調査: ターン制をやめてアクションにできるか

**この調査で何を決めたいのか**: ISS-09 / ISS-02。リアルタイムのアクションゲーム
（Unity・3D も可）にした場合、期間・決定論・工数がどうなるか。

調査日: 2026-09-02 / → ADR 候補 / 対象 ISS-09, ISS-02（ADR-0001）
ユーザー指摘 2026-09-02：「ターン制は渋くないか。Unity でアクションゲーム的に。
指一本で赤ちゃんの動きを決めて、あとはボタンで行動を選ぶ。3D でもいい」

## 1. 「操作しづらさが笑いになる」は確立したジャンル

- **Octodad は QWOP に機械的な着想を得ている。**QWOP は 4 つのキーで走者の
  4 本の手足を操作する 2008 年の Flash ゲームで、
  自律的な筋肉の制御を、意識的に操作する別々の作業に翻訳した
- **Human: Fall Flat** は「意図的に難しい（intentionally difficult）」領域にあり、
  Octodad と同じ場所に位置づけられる。ぎこちない物理を持ち、
  一歩一歩が誇張され、キャラクターがよろめく
- Surgeon Simulator は、**意図的に不器用で苛立たしくあろうとすること**を
  テーマ的な特徴にしている

> 出典: [Human: Fall Flat - Wikipedia](https://en.wikipedia.org/wiki/Human:_Fall_Flat)（2026-09-02 アクセス）
> 出典: [From the Archives: Octodad: Dadliest Catch](https://limitedrungames.com/blogs/news/from-the-archives-octodad-dadliest-catch)（Limited Run Games、2026-09-02 アクセス）
> 出典: [Review: Human: Fall Flat (PC)](https://www.digitallydownloaded.net/2016/08/review-human-fall-flat-pc.html)（Digitally Downloaded、2026-09-02 アクセス）

**この方向は、これまでの調査と強く整合する。**
Gartic Phone の「絵が下手なほど面白い」（→ [game_mechanic.md](game_mechanic.md) 1 節）と
同じ原理で、**片手のぎこちなさが面白さの供給源になる。**

### ただし警告がある

> 笑って進むか、コントローラーを壊すかは、
> **その意図的に苛立たしい操作系への耐性次第**である

出典は上記 Digitally Downloaded / Gaming Trend のレビュー。

**寝かしつけ直後の、疲れて苛立っている親に、苛立つ操作を渡すことになる。**
これは題材と操作系が二重に負荷をかける構図であり、外し方によっては不快になる。

## 2. Unity は標準では決定論的でない（ADR-0002 と衝突する）

- **FixedUpdate は現実時間で一定間隔に呼ばれるものではない。**
  物理演算のタイミングを「Unity におけるゲーム内の時間」で一定にする、という定義である
- 固定タイムステップはリアルタイムで物理シミュレーションを正確に保つが、
  物理を多用すると問題を起こし、フレームレートも下がりうる
- Unity で決定論的な物理を実現するには **deterministic-physics のような
  別ソリューションの導入が必要**（＝標準の物理は決定論的でない）

> 出典: [【Unity検証】FixedUpdateは本当に一定間隔なのか](https://dkrevel.com/unity-explain/fixedupdate-fixed-timestep/)（2026-09-02 アクセス）
> 出典: [決定論的な物理演算を実現するdeterministic-physicsを導入する上でつまづいたこと【Unity】](https://amagamina.jp/blog/unity-deterministic-physics/)（アマガミナブログ、2026-09-02 アクセス）
> 出典: [タイムとフレームレートの管理 - Unity マニュアル](https://docs.unity3d.com/ja/2019.4/Manual/TimeFrameManagement.html)（2026-09-02 アクセス）

### これは既存 ADR を覆す提案になりうる

[ADR-0002](../decisions/ADR-0002-test-harness.md) は **Accepted** であり、
決定論の 4 条件（シード注入 / クロック注入 / I/O 差し替え / 失敗時のシード出力）と、
「主戦場は harness 層」を確定させている。

**物理エンジンに乗せた瞬間、この前提が崩れる。**
[research スキル](../../../.claude/skills/research/SKILL.md) の規約に従い、
握りつぶさずに明示する。回避策は 3 つある。

| # | 回避策 | 内容 | 代償 |
| --- | --- | --- | --- |
| P-1 | **物理エンジンを使わない** | Rigidbody を使わず、座標を自前で計算する。固定タイムステップ + 入力列の記録で完全再現（格闘ゲームやRTSのリプレイ方式） | 表現がぎこちなくなる（が、それは今回**むしろ利点**） |
| P-2 | 決定論的物理ライブラリを入れる | deterministic-physics 等 | 導入コスト。個人開発 2〜3 週間には重い |
| P-3 | ADR-0002 を部分的に覆す | 描画・物理層は決定論の対象外とし、ゲームロジック層のみ決定論を保つ | **新しい ADR の起案が必要。**ハーネスの守備範囲が縮む |

**P-1 が最も筋が良い。**「操作がぎこちない」ことが売りである以上、
高級な物理は要らない。自前の簡素な運動計算で足り、決定論も守れる。

## 3. 工数の現実

- Unity の Asset Store には既成のモデル・音楽・スクリプトが豊富にあり、
  活用すれば開発時間を大幅に短縮できる
- 事例：2D ゲームで**制作期間 約 3 か月**。未経験者が初の iPhone アプリを **7 日間**で開発
- 初心者の失敗あるあるとして「**ついスケールが大きすぎるゲームを作り始めて挫折する**」
  が挙げられている
- Android 向けビルドには Android Studio のインストールと Unity 側の設定が必要

> 出典: [個人ゲーム開発の全体の流れを解説！](https://yurinchi2525.com/20231011startmakinggame/)（ゲ制工房、2026-09-02 アクセス）
> 出典: [初心者でもできる！ 7日間で作るUnityゲーム開発](https://gihyo.jp/dev/serial/01/7days-unity)（gihyo.jp、2026-09-02 アクセス）
> 出典: [Android 用の開発を始める - Unity マニュアル](https://docs.unity3d.com/ja/2023.2/Manual/android-getting-started.html)（2026-09-02 アクセス）

### 3D の追加コスト

赤ちゃん・親・寝室のモデルとアニメーションが要る。Asset Store で揃う可能性はあるが、
**「親が赤ちゃんをトントンする」「布団に置く」といった固有の動きは既成品に無い。**
自作するとアニメーション工数が跳ねる。

**無音・バイブ禁止の制約は、ここでは有利に働く。**音のアセットが一切要らない。

## 4. トリレンマ

**「2〜3 週間」「Unity 3D アクション」「ADR-0002 の決定論」は、同時に満たせない可能性が高い。**
どれかを動かす必要がある。

| 動かすもの | 結果 |
| --- | --- |
| **期間を延ばす** | 3D アクションを狙える。ただし ADR-0002 の扱いは別途決める必要がある |
| **3D を諦める（2D にする）** | 2〜3 週間に近づく。ぎこちなさは操作方式で作れるので、笑いは失われない |
| **物理エンジンを諦める（P-1）** | 決定論を守れる。表現はぎこちなくなるが、それは今回**利点** |
| **アクションを諦める** | ターン制に戻る。ユーザーが「渋い」と判断済み |

## 5. 手触りの案（指一本 + ボタン）

ユーザー案「指一本で赤ちゃんの動きを決めて、あとはボタンで行動を選ぶ」を、
[game_mechanic_4.md](game_mechanic_4.md) のジレンマと接続する。

- **指のドラッグ**：赤ちゃんの体を動かす（寝返り、ずりばい、反り返り）。
  思い通りに動かない手触りを意図的に作る（Octodad 原則）
- **ボタン**：「泣く」「ぐずる」など、状態を変える行動
- **親はリアルタイムで反応する**：覚醒度が上がる／トントンが来る／布団に置かれる
- ジレンマは維持できる：待つほど深く眠る、対処には損得の両面がある、
  「置かれた瞬間」の一撃は一度しか通じない

**ターン制で設計したジレンマは、リアルタイムでもそのまま使える。**
違いは「考える時間が無制限か、有限か」だけである。
むしろリアルタイムのほうが「置かれた瞬間」の緊張は出しやすい。

## この調査から導く結論（→ ADR 候補）

1. **アクション化の方向は、これまでの調査と整合する。**「操作しづらさが笑いになる」は
   確立したジャンルであり、片手・暗所という制約がそのまま面白さの供給源になる
2. **ただし Unity 標準の物理に乗ると ADR-0002 と衝突する。**
   回避策 P-1（物理エンジンを使わず自前計算）が最も筋が良く、
   「ぎこちなさが売り」という性質とも一致する
3. **「2〜3 週間 / 3D / 決定論」は同時に satisfy できない。**
   何を動かすかはユーザーの判断
4. 苛立つ操作系は、**疲れた親に対して二重の負荷**になりうる。題材との組み合わせに注意が要る
