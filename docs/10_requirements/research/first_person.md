# 調査: 一人称視点の赤ちゃんは成立するか

**この調査で何を決めたいのか**: ISS-09。一人称視点を採るか。
採る場合、生後 1 か月（動けない）とハイハイ期のどちらにするか。

調査日: 2026-09-02 / → ADR 候補 / 対象 ISS-09
ユーザー指摘 2026-09-02：「Unity でも期限は間に合うと思う。赤ちゃんを FPS みたいな視点で
動かして何かするのがいい。現在の動けない時でもいいし、これからのハイハイができる時でもいい」

## 1. 3D 酔いが最大のリスク。そして段階の選択がそれを決める

- 3D 酔いは、視覚情報と前庭感覚のズレが原因。**特に上下動が大きい動きが酔いを誘発する**
- 一人称視点は、三人称に比べて見える範囲が狭く、
  カメラを振ってしまいがちで**酔いやすい特性**がある
- 対策として、**キャラクターが歩くときの上下揺れを OFF にすると大幅に改善する**場合がある
- カメラが意図しない方向に急にパン・ズームすることも原因になる

> 出典: [画面酔い・ゲーム酔いの治し方8選｜FOV・モーションブラー設定で今すぐ軽減](https://gaming-st.com/trouble-settings/3d-motion-sickness-guide/)（2026-09-02 アクセス）
> 出典: [3D酔い（ゲーム酔い）を克服!!その原因と7つの対策](https://www.bauhutte.jp/bauhutte-life/simulator-sickness/)（Bauhütte、2026-09-02 アクセス）

### これが段階の選択を決める

| 段階 | カメラの動き | 酔いリスク |
| --- | --- | --- |
| **生後 1 か月（動けない）** | 仰向けで固定。首を振る程度。**移動による上下動が無い** | **低い** |
| ハイハイ期 | 床すれすれを這う。上下動が連続する | **最も高い構成** |

**ハイハイは、3D 酔いの条件を全て満たしてしまう。**
床すれすれ・一人称・連続する上下動。夜中に、赤ちゃんを抱えた状態で遊ぶゲームとしては
危険が大きい。

**動けない段階のほうが、酔いにくく、工数も低く、ペルソナの現在（生後 1 か月）とも一致する。**

## 3. 一人称であることが、既存の設計を強化する

[game_mechanic_4.md](game_mechanic_4.md) で設計した 3 つのジレンマは、
一人称にすると**表現として自然に成立する。**

| 設計要素 | 一人称での表現 |
| --- | --- |
| 親の覚醒度 | 覗き込んでくる顔、伸びてくる手として見える。数値を表示しなくてよい |
| トントン | 視界の上から手が来る |
| 抱っこ | 世界が持ち上がって回転する（**酔い対策として、ゆっくり・揺れ最小に制御する必要**） |
| **置かれる瞬間** | 視界が下がり、天井が遠ざかる。**背中が布団に触れる**。ここが最大の一撃のタイミング |
| **寝たふり** | **目を閉じる＝画面が暗くなる。**閉じている間は何も見えない |

**「寝たふりのリスク」が、画面表現としてそのまま成立する。**
目を閉じている間は情報が取れない。いつ目を開けるかが賭けになる。
数値やUIで説明する必要が無く、**当事者でなくても一瞬で理解できる。**

さらに、**目を閉じると画面が暗くなる**という挙動は、
「暗所で遊ぶ・画面を明るくできない」という制約とも噛み合う。

## 4. 操作（ユーザー案との接続）

ユーザー案「指一本で動きを決めて、ボタンで行動を選ぶ」をそのまま適用できる。

- **指のドラッグ**：首を振る／視線を動かす。**可動範囲は狭い**（首がすわっていない）。
  思い通りに動かない手触りは Octodad 原則（→ [action_game.md](action_game.md) 1 節）に沿う
- **ボタン**：泣く / ぐずる / 手足をばたつかせる / 目を閉じる
- **移動しない。**これが酔い対策であり、工数削減であり、
  かつ「生後 1 か月は動けない」という事実そのもの

### 「動けないこと」がテーマになる

プレイヤーは自力で何もできない。**泣くこと、目を開けること、手足を動かすことだけで、
親という巨大な存在を動かす。**間接的にしか世界に干渉できない。

これは赤ちゃんの実態そのものであり、笑いにも、それ以外の感情にもなりうる。
**制約が主題になっている**という点で、これまでの設計方針と一貫している。

## 5. 工数への影響

[action_game.md](action_game.md) 4 節のトリレンマが緩む。

- **移動が無い** → 地形・当たり判定・移動アニメーションが不要
- **視点が固定位置** → 3D 空間は寝室 1 部屋、しかも見える範囲だけでよい
- **必要なアニメーションは親の手と顔のみ**（トントン、抱き上げ、置く）
- 音アセットは不要（無音・バイブ禁止）

**3D を採っても、範囲が極端に狭いので 2〜3 週間に乗る可能性がある。**
ただし Asset Store で「親が赤ちゃんをトントンする」動きは手に入らないため、
そこは自作になる（→ action_game.md 3 節）。

## 6. 拡張の道筋

段階を後から足せる。生後 1 か月（動けない）→ 寝返り → ハイハイ、と
**子の成長に合わせてゲームが増える。**

本企画は「困りごとを解くアプリ」ではなく贈り物として整理されている
（→ [concept_draft.md](../concept_draft.md)）。
**子の成長と一緒に育つ**という性質は、その位置づけと強く整合する。

ただしハイハイ期は 1 節の酔いリスクを抱えるため、
**採用するとしても後回しにし、酔い対策を別途設計する必要がある。**

## この調査から導く結論（→ ADR 候補）

**一人称視点を採り、段階は「生後 1 か月（動けない）」にする。**

1. 3D 酔いのリスクが最も低い（移動による上下動が無い）
2. 工数が最も低い（移動・地形・移動アニメーションが不要）
3. ペルソナの現在（生後 1 か月）と一致する
4. 「寝たふり＝目を閉じる＝画面が暗くなる」が、
   設計済みのジレンマを説明なしで成立させる
5. 「動けないこと」が制約であると同時に主題になる

**ハイハイ期は拡張として残す。**酔い対策の設計が別途必要。
