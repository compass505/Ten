# 調査: M-1 / M-2 を詰める（乱数と笑いをどこに置くか）

**この調査で何を決めたいのか**: ISS-09。M-2（立場逆転）を軸に、
乱数をどこで出すか、笑いをどこで出すかを、コンセプトを判断できる粒度まで詰める。

調査日: 2026-09-01 / → ADR 候補 / 対象 ISS-09
ユーザー指摘 2026-09-01：「M-1, M-2 寄りで、ランダム要素や笑える要素をどこで出すか。
今のところ M-2 の発想が一番面白そう」

> **これは基本設計ではない。**画面設計・データ構造・実装方針には踏み込まない。
> ここで決めたいのは「何を作るか」だけ。

## 1. 乱数をどこに置くか（構造の核）

Slay the Spire のデイリークライムは、シード固定でルートも敵も完全に同じだが、
**複数の乱数生成器が使われているため、プレイ方法によって結果が異なる**
（→ [game_mechanic_2.md](game_mechanic_2.md) 1 節）。

ここから原則が導ける。

### 原則：乱数は「盤面の生成」に使い、「勝敗の決定」には使わない

| 使う | 使わない |
| --- | --- |
| その日の盤面（親の初期状態、手札の並び、起きる出来事）を作る | プレイヤーの選択の成否を、選択と無関係に決める |

- **盤面はシードで固定される** → 夫婦は同じ日の同じ状況を遊ぶ → 見せ合う意味が生まれる
- **結果の差はプレイヤーの選択だけから出る** → 「お前そこでその手を使うのかよ」が笑いになる
- 乱数は消費されるが、**消費の順序がプレイヤーの選択で変わる**ため、結果は分岐する

**これが「問題を解く」との違いでもある。**乱数を一切使わないと詰将棋になり、
[scope.md](../scope.md) で却下した「正解のあるゲーム」に戻ってしまう。
乱数はあるが再現可能、という状態を保つ。

これは [ADR-0002](../decisions/ADR-0002-test-harness.md) の
シード注入・クロック注入と完全に一致する。テストのために設計を歪める必要が無い。

### 日替わりシードの作り方

日付（＋固定の文字列）からシードを決める。**時計を直接読まない**（ADR-0002 の D2）。
過去の日には戻れない（Wordle 方式 → [game_direction.md](game_direction.md) 2 節）。

## 2. 笑いをどこに置くか

笑いは 3 箇所に分散して置ける。**主戦場は 3 番目である。**

### (a) 語彙 — 当事者にしか分からない言葉

「背中スイッチ」「反り返り」「置いた瞬間」「オムツ替えの最中に追加」のような、
経験者にだけ通じる語で行動や出来事に名前を付ける。
**説明された瞬間に面白くなくなるので、説明しない。**

### (b) 実況 — 親の心の声がズレていく

「パパは『よし、寝た』と思った」の直後に起きることを見せる。
親が状況を誤認している様子が読めると、当事者は自分を見ることになる。

### (c) 共有テキスト — ここが本体

**笑いが実際に起きるのは、夫婦が結果を見せ合った瞬間である。**
したがって共有テキストの設計が、このゲームで最も重要な要素になる。

Wordle は 3 色の四角が整然と並ぶキャッチーさを守るため、
共有文にゲームの URL を入れることをやめている（→ game_direction.md 2 節）。
**共有テキストは「削って強くする」対象であって、情報を足す場所ではない。**

一晩の経過が絵文字の並びで一目で分かり、相手のものと並べたときに
どこで何が起きたかが伝わる形を目指す。具体的な記法は未定。

## 3. M-2（立場逆転）の中身

**プレイヤーは赤ちゃんになり、親を起こす側に回る。**

- 夜から朝までが 1 回。プレイヤーは「泣く」「反り返る」「背中スイッチ」等の手を選ぶ
- 親（コンピュータ）はトントン・ミルク・抱っこ等で対抗してくる
- **親は慣れる。**同じ手は効かなくなるので、手を変える必要がある
- 朝まで何回起こせたかが結果になる

### なぜ M-1 より筋が良いか

| 観点 | M-1（親側でサバイバル） | M-2（赤ちゃん側） |
| --- | --- | --- |
| 体験 | 大変さの**再演**。寝かしつけ直後にやりたいか疑問が残る | 大変さの**反転**。加害側に回るので、同じ素材が笑いに変わる |
| 共感の出方 | 「わかる、つらい」 | 「わかる、これやられた」 |
| 夫婦の関係 | 各自が別々に耐える | **二人とも赤ちゃん側**になり、共通の相手（親役）ができる |
| 前例 | 育児シミュレーションは既存にある | 見つからなかった（空いているのか成立しないのか不明） |

**M-2 では、現実では二人とも親である夫婦が、ゲームの中では二人とも赤ちゃんになる。**
この反転自体が共感の構造になっている。

### 差別化の核心（既存アプリが構造上持てないもの）

**主人公を自分の子にできる。**名前を Ten にすれば、
そのゲームは Ten が親を起こす話になる。

これは商用アプリが原理的に持てない。
本企画が「困りごとを解くアプリ」ではなく「贈り物」である
（→ [concept_draft.md](../concept_draft.md) 方向転換の記録）ことと整合する。
**「わざわざ作る良さ」は、ここに置くのが最も強い。**

## 4. 制約の担保

| 制約 | 担保の仕方 |
| --- | --- |
| 片手（親指のみ） | 操作をタップだけにする。選択肢は画面下部に置く |
| 暗所 | 暗い配色を前提にする。明るい背景を使わない |
| 無音 | 音を鳴らさない。**バイブも使わない**（赤ちゃんを起こす） |
| 中断される | ターンの切れ目でいつでも閉じられ、再開できる |
| 通信なし | 結果テキストを既存の手段（LINE 等）に貼るだけ |
| 2〜3 週間 | 1 画面 + テキスト中心。凝った演出を持たない |

**無音・バイブ禁止は、演出手段を大きく制限する。**
笑いを音やアニメーションで作れないため、
**言葉と間で作るしかない**。これは 2 節の (a)(b)(c) と整合する。

## 5. 未確認 / この案が崩れる条件

- **本人が「育児をネタにしたゲーム」を遊びたいか**（未確認。最重要）
- 配偶者が同じ感覚を持つか。片方だけが面白がると、見せ合いが成立しない
- 配偶者の端末（iOS / Android）。**未確認**。scope.md は現在 iOS を除外している
- 「親を起こす」という題材を、当人が笑えるか。
  産後の状況によっては笑えない可能性がある（**本人未確認**）

## この調査から導く結論（→ ADR 候補）

**M-2 を軸に据える。** 決め手は 3 点。

1. 乱数を「盤面の生成」に限れば、夫婦が同じ状況を遊びつつ、
   結果の差が選択だけから出る。見せ合う意味が生まれ、ADR-0002 とも一致する
2. 立場の反転により、大変さの再演にならずに同じ素材を笑いに変えられる
3. **主人公を自分の子にできる**という、商用アプリが構造上持てない差別化がある

**ただし 5 節の未確認が埋まっていない。**特に「育児をネタにしたゲームを遊びたいか」は、
外れると企画全体が成立しない。ADR に起案する場合は、
**根拠が仮説であることを明記する必要がある。**
